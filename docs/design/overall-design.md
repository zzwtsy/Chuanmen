# Chuanmen · 总体设计文档

设计基线：2026-10-11。本文维护产品与交互契约；网络接入细节见 [技术架构](technical-architecture.md)，现有工程入口见 [README](../../README.md)，实施顺序与阶段状态见 [路线图](../plan/ROADMAP.md)。设计表达不代表产品实现已验收；上游来源按研究记录的核对日期理解。

## 1. 产品目标

面向希望在 Android 上加入、管理并排查 EasyTier 虚拟网络的用户。首次使用应能快速连接；日常打开应能马上看到网络是否运行、虚拟 IP、设备情况和大致流量趋势；需要高级配置时能在同一份表单中找到能力，不必切换到另一个具有不同状态的“专家模式”。

产品采用原生 Kotlin / Jetpack Compose，沿用 Material 3 的组件行为并体现 Expressive 的形状、层级和选中反馈，支持系统动态取色。当前 HTML 用来确认信息结构和交互，不作为 WebView 上线方案。

成功标准是操作可预测、运行状态可信、配置完整且不丢失。界面不会用动画、数据占位或按钮点击结果代替真实的 VPN 状态。

## 2. 设计范围与不可破坏的约束

| 领域 | 固定决定 |
|---|---|
| 运行模式 | 免 Root；系统 VPN 权限；同一时刻一个活动实例；多个本地配置 |
| 导航 | 总览、设备、配置、日志四个主目的地；设置在应用栏 |
| 配置名称 | 本地元数据，与网络名称、设备 hostname 和核心 instance_name 不混用 |
| 表单模式 | 基础配置 / 完整配置；同一草稿与错误状态 |
| 保存应用 | 保存、核心应用、VPN 重建有独立结果；不默默断开或换网 |
| 设备 | 原地展开优先；一个集中详情面；没有相关日志入口 |
| 流量 | 当前上下行与最近 60 秒纯趋势；范围在设置 |
| 日志 | 核心与 App 双来源；采集级别与显示筛选分离 |
| 正常反馈 | 干净状态无配置横条；有待处理事项时才显示操作区 |

不默认建设账号、云同步、Web 管理后台或 App 内 AI 功能。AI 友好是工程可理解、可复现和可验证的属性。

## 3. 信息架构

### 3.1 公共应用框架

应用栏显示当前查看的配置名称及必要状态；网络选择器支持查看、添加和管理配置。主导航维持稳定位置，页面与表单共享一个底部操作区域，避免顶部横条、浮动按钮和页面内按钮同时表达同一件事。

查看其他配置不会改变正在运行的网络。若查看对象与运行对象不同，应用框架显示简洁的“另一个网络正在运行”说明和返回查看入口。用户发起连接时才进入明确的切换流程。

返回遵循最小关闭顺序：先关闭对话框或底部弹层，再关闭设备详情或设置，最后返回前一个导航层级。主导航切换保留合理滚动和草稿状态；表单错误不因返回或切标签消失。

### 3.2 页面职责

| 页面 | 用户要回答的问题 | 核心内容 | 次级内容 |
|---|---|---|---|
| 总览 | 网络是否在运行？是否有程序经过它？ | 虚拟网络卡片、连接动作、当前上下行与趋势 | 需要处理的运行异常 |
| 设备 | 谁在线？怎样连接？通信质量如何？ | 设备列表、直连/中继、IP、展开指标 | 集中详情、可复制地址 |
| 配置 | 怎样接入？怎样调整行为？ | 基础/完整标签、共享表单、按需操作区 | 字段搜索、组内帮助、导入导出 |
| 日志 | 刚才发生了什么？ | 双来源、级别/关键词筛选、稳定阅读 | 采集设置、脱敏导出 |
| 设置 | App 怎样工作？哪些流量走 VPN？ | 动态取色、主题、流量范围、系统相关偏好 | 关于、版本、许可与诊断入口 |

## 4. 总览

### 4.1 虚拟网络卡片

卡片内容按决策顺序排列：连接状态与当前配置、虚拟 IP、在线设备及直连/中继摘要、连接或断开动作。复制按钮紧邻 IP，形状、位置和语义在设备详情中复用。

“在线设备”不再单独占一个重复卡片。点击摘要可以进入设备主页面并保留当前网络上下文，不新造一层“在线设备”详情路由。

首次没有配置时展示添加配置入口；有配置未连接时展示连接动作；连接中允许取消；失败时保留可理解的原因和重试。处于已连接状态但没有业务流量是正常状态。

### 4.2 实时流量

当前发送、接收速率位于图表上方，图表占据卡片主要空间。固定最近 60 秒窗口，前台显示时建议每秒补一个采样点；不足 60 个点时展示已有数据，不用随机值补齐。

图表没有时间段按钮、详情按钮、拖动取值、hover 读数、图例开关或暂停回看。纵轴按当前数据稳定缩放，可快速增大、缓慢回落；零流量不伪造波动。上下行使用稳定的两种主题颜色并配方向/文字，颜色不承载唯一语义。

**数据契约：**

- `txBytes` 表示从本机 TUN 成功读出的 IP 字节；`rxBytes` 表示成功写回本机 TUN 的 IP 字节。包括经过该路径的 DNS 和系统流量，不是应用有效载荷，也不证明对端已收到或本机应用已消费。P00 提供限定探针的计数证据，P02 仍须确认正式产品的计数位置与身份。
- 首选在已有 TUN 数据通路记录累计字节，不能为图表另起一个读取者消费同一个 TUN fd。
- 速率来自同一 `sessionEpoch` 内累计计数差值除以单调时间差；重连、计数重置或缺样时断开曲线，不画负速率。
- 核心心跳、加密封装、socket 保活和帮助第三方中继的字节不能伪装成本机 App 流量。
- `0` 表示测得无流量；`null` 表示没有可用测量。后者显示“暂无数据”，不能当零。
- 页面隐藏后暂停高频 UI 更新；不为图表维持额外后台唤醒。

流量曲线能说明当前测量口径下有字节通过，不能单独证明所有目的地址、DNS、默认出口和双向业务都正常。产品不需要常驻解释这条技术边界，但连接状态与流量状态在模型中必须分开。

## 5. 设备

### 5.1 列表与展开

默认列表保留辨识和决策所需的信息：名称、本机标记、虚拟 IP、在线状态、直连/中继，以及可用的延迟摘要。点击设备主要区域原地展开，展示 NAT、核心版本和流量摘要；不要让每个指标都跳转新页面。

集中详情在手机窄屏可用一个详情面或可返回页面，宽屏可用列表旁的详情面。入口只有一个，保持列表滚动、选择与过滤状态。实现哪种容器由窗口尺寸决定，信息层级保持一致。

### 5.2 数据模型与未知状态

| 指标 | 表示什么 | 不可用时 |
|---|---|---|
| NAT 类型 | 核心报告的探测结果，并保留更新时间 | 未知 / 尚未探测，不能推测 |
| EasyTier 版本 | 当前设备报告的核心版本 | 未报告，不用本机版本补齐 |
| Tx/Rx 字节与包数 | 明确标注的链路或设备统计范围 | 未提供，不能以 0 代替 |
| Tx/Rx 速率 | 相同统计主体和采样周期的差值 | 暂无数据 / 已过期 |
| 延迟 | 核心对所示链路或探测目标的测量 | 未测得 |
| 探测丢包 | 探测样本的丢失比例和可用窗口 | 样本不足；不能叫业务丢包 |
| 路径 | 直连、中继及核心能够确认的下一跳 | 未知路径，不拼造完整拓扑 |

中继设备的端到端数据若无法单独计量，应显示不可用或清楚标注“中继链路”；不能把与中继节点的所有流量替换为某个远端设备的数据。快照应含 `observedAt`、有效性和来源范围，离线时保留最后观测值但不能继续称实时。

### 5.3 复制

虚拟 IP 使用与总览相同的共享组件，独立可聚焦、具备“复制 IP”语义。用户要求短暂复制成功提示：原型使用 Toast；原生 Android 12L 及以下显示短 Toast，Android 13 及以上优先采用系统剪贴板反馈，避免重复弹出。只有实际写入剪贴板成功才提示成功。[Android 复制反馈](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste)

设备卡片与详情没有“相关日志”按钮。需要排查时用户使用稳定的日志主目的地，避免设备页面变成多条诊断支线。

## 6. 配置系统

### 6.1 范围与来源

配置目录以 [官网实际部署助手](https://easytier.cn/assistant/) 的可见编辑项为基线。当前快照为 **37 个核心编辑单元 + 7 个 Android 设置**，分成六组；复合项可能包含多个子字段，不能与核心 flags 数量相等同。

核心 CLI、protobuf 和主分支可能有比线上助手更多的字段。它们可以帮助理解语义，但不能自动扩充用户要求的表单范围。线上部署不能确定 commit 时，用下载资源的哈希固定证据，不把 GitHub main 当成部署版本。快照中的 8 个隐藏项须按选定核心与平台证据复审，P00 记录作为历史依据：平台托管、确实不适用与暂未实现分别记录；`ipv6_public_addr_auto` 的历史理由是尚未适配，不能据此永久从 Android 功能中删除。37+7 是原型快照数量，不是未来能力上限。

快照中的 `coreSemanticsRevision` 是早前原型研究依据，与实际选用的核心来源不是一个概念。产品接入与核心升级须核对字段名、缺省值、序列化和热应用能力；P00 解析实验不代表正式产品的热应用已完成。

### 6.2 基础配置

固定三个主要输入：网络名称、网络密码、连接节点。地址方式以摘要显示，默认新建建议自动分配 IPv4；已有静态配置必须如实显示，不能切回基础标签就重置为自动。

“基础”是最低必要操作集合，不代表三个字段在所有核心模式下都无条件必填。字段要求由选定连接方式和实际核心规则确定，例如 missing secret 与空字符串并不相同；无引导节点的独立实例是否允许，应由原生验证和明确产品行为决定。

新建配置对话框另有“配置名称（可选）”，用于本地识别，空时以网络名称显示。这个元数据不挤进连接配置的必填集合。

### 6.3 完整配置

| 组 | 内容 | 默认呈现原则 |
|---|---|---|
| 网络与地址 | 网络身份、设备名称、IPv4、底层 IPv6、MagicDNS | 接入相关优先；条件输入按当前模式展开 |
| 节点与直连 | 节点、监听、公布地址、P2P 与打洞 | 节点列表可直接编辑，低频开关在组内 |
| 路由与服务 | 路由、出口、分享子网、SOCKS5、转发、Portal | 先启用服务，再展开其参数 |
| 安全与访问 | 加密、私有模式、ACL | 使用明确的正向文案，反向核心 flag 单独映射 |
| 中继与性能 | 延迟优先、MTU、限速、中继规则、KCP/QUIC | 展示默认含义与依赖关系 |
| Android 应用设置 | 应用范围、互联网流量、IPv6、DNS、自动重连 | 明确这是平台策略，不写入核心 TOML |

完整配置采用同页分组展开和字段搜索，不为每个配置组新增路由。搜索命中后自动展开组，必要时显示其启用依赖。帮助就近展开，只讲当前决策所需的内容。

应用设置中的流量范围可从设置入口到达同一策略编辑状态。不能在总览另造一份范围选择器，也不能让设置和配置维护两套不一致的数据。

### 6.4 草稿、保存、运行

建议的数据边界如下，具体类型在 P03 建立：

| 状态 | 内容 | 所有者 |
|---|---|---|
| `ProfileMetadata` | UUID、本地 label、排序等 | 本地仓库 |
| `ConfigDraft` | 原始输入、规范化值、错误、dirty 字段 | 编辑状态层；按 profile 隔离 |
| `SavedProfile` | 已持久化核心文档、平台策略与版本 | 数据层 |
| `AppliedSnapshot` | 实际会话、核心与 VPN 策略指纹、运行地址 | 服务/运行协调器 |
| `RuntimeState` | 连接阶段、失败、设备与统计快照 | 运行服务 |

原型的 `profile.label` 在原生工程中统一映射到 **`ProfileMetadata.localDisplayName`**。这是同一语义的跨原型/原生命名映射，不能在原生模型中再保留 `label`、`displayName` 等并行字段或双写。修改只更新元数据，不能改核心配置、提升核心修订号、创建待应用状态或覆盖运行参数；保存核心、导入合并和恢复运行快照也不能抹掉用户的本地名称。

原始输入与规范化值分开存储。例如用户输入一个不合法 CIDR，错误应该附着原始字符串，不能为了恢复类型正确把它清空；切标签、搜索或折叠组不丢原文。

保存会进行校验和持久化，成功后产生新的 saved 版本。只有存在同一配置的活动会话（`activeSession.profileId == editedProfileId`），且核心或 VPN 策略有差异，才进入待应用；离线保存或另一个配置正在运行时，本配置直接进入已保存。App 即时设置的差异单独分类，不因本地显示偏好而重启 VPN。

### 6.5 按需操作区

| 当前情况 | 页面表现 | 可用动作 |
|---|---|---|
| 干净且运行内容一致 | 直接显示表单，无状态横条 | 正常编辑 |
| 离线且已保存 | 无状态横条；保存成功短提示 | 继续编辑或去连接 |
| 有未保存改动 | 底部共享操作区 | 保存、放弃本轮改动 |
| 有校验错误 | 字段错误 + 底部简洁摘要 | 定位错误，不可伪成功 |
| 当前配置正在运行且有已保存差异 | 底部待应用状态 | 查看影响并应用；必要时重连 |
| 正在保存/应用 | 同一区域显示进度，防重复 | 可取消的操作才提供取消 |
| 操作失败 | 保留输入与可重试原因 | 重试或恢复；不自动吞错 |

保存成功使用约 3.6 秒 Snackbar，不把“配置已应用”常驻在标签下。错误、待应用和正在操作属于持续状态；不能套用同一短暂计时器。[Android Snackbar](https://developer.android.com/develop/ui/compose/components/snackbar)

### 6.6 应用与回退

应用前构建 `ChangePlan`：哪些只是 App 即时设置，哪些要更新核心，哪些要重建 VpnService。未验证热更新的字段按明确的重连路径处理，不能因为原型写了 `core-hot` 就直接宣称支持。

运行快照只在实际成功后更新。核心返回已接受、任务已排队或 JNI 返回零不等于地址、路由、DNS 已生效。失败时保存版本可以保留，运行快照仍代表最后成功会话；如果旧连接已停止，UI 也必须显示停止或失败，不能宣称已回滚在线。

### 6.7 导入、导出与未知项

导入需要大小限制、语法校验、字段差异预览、秘密遮蔽和名字冲突处理。Android 不适用项从表单与搜索排除，但不能在往返保存时无提示删除已有数据。

保留未知字段不等于无条件执行它们：保留原始文档用于导出/恢复；交给核心的有效配置由已验证的解析与策略决定。对无法安全表示或支持的内容，给出字段级诊断和可选择的处理方式。

原型中的脱敏配置预览不是完整的生产 TOML 兼容性保证。P03/P05 必须用选定版本的核心解析器和 golden 样例验证 missing、empty、默认值、反向布尔、CIDR、URI、嵌套结构和 Unicode。

## 7. 日志与诊断

日志页同时支持 EasyTier 和 App 两个来源。默认展示适合日常排查的级别，来源、级别、关键词用于显示筛选；更改采集级别是另一个明确设置，可能影响性能与保留量。

每条结构化记录建议包含时间、单调顺序号、来源、级别、模块、会话标识和消息。不要用网络秘密、私钥或含凭据 URI 作为关联键。设备关联若存在也属于日志过滤能力，不在设备页扩散入口。

滚动到历史记录后停止自动跟随，并出现新增条数提示；用户点击后返回底部。过滤与导出不应阻塞主线程。采用有界内存缓冲及轮转存储，保存量和清理策略有上限。

脱敏在写入/导出前按场景处理，日志级别提高也不能解除秘密保护。诊断包由用户发起，展示包含哪些文件，剔除私钥、密码和原始凭据。导出通过系统文件/分享流程，不能自动上传。

## 8. Android 原生体验

### 8.1 主题与组件

系统动态色在 Android 12 及以上从系统读取；旧系统回退到品牌色。用户可选择跟随系统、浅色或深色，动态色是否开启与明暗主题分别建模。[Material 3 Compose 主题](https://developer.android.com/develop/ui/compose/designsystems/material3)

Expressive 的落地使用更清楚的大小层级、选中形状、分组与动作强调。不要为“有表现力”给所有卡片彩色背景、让连接按钮持续跳动或给每次页面切换增加戏剧化动画。实验性 API 的版本与封装决策见技术架构，不在计划中假定所有 Expressive 组件已稳定。

高频交互优先使用平台组件：导航栏、Tabs、开关、列表项、文本框、对话框、底部弹层、Snackbar。自定义曲线应以准确测量和可访问性为前提，控制其依赖成本。

### 8.2 可访问性与适配

交互目标以 Android 推荐的至少 48 dp 为基线，图标按钮提供内容描述；支持 TalkBack、键盘焦点、深浅色和大字体。状态同时以文字/图形表达，不依赖颜色。动态图表提供当前数值与简短无障碍描述，不每秒朗读全部采样点。[Compose 可访问性](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)

适配小屏、横屏、分屏、折叠屏、系统栏和 IME。键盘出现时当前字段与保存动作仍可到达，长表单不会被固定高度容器截断。减少动态效果偏好下使用简单状态过渡。

### 8.3 系统集成

VpnService 授权拒绝、授权撤销、其他 VPN 接管、前台服务通知、进程终止、系统 Always-on 和用户主动断开应有明确结果。快捷开关与通知动作只是同一个运行协调器的入口，不另建连接状态。

自动重连只处理明确授权且符合策略的恢复场景。用户主动断开必须清除自动恢复意图；选择查看另一个配置也不能改变恢复目标。具体系统规则、后台启动限制和前台服务类型依据当前 Android 官方资料，并通过 P02/P06 真机验证。[Android VPN](https://developer.android.com/develop/connectivity/vpn)

## 9. 工程与验证边界

采用包级业务切片：配置、日志等能力聚合自己的状态、规则、持久化与测试；应用装配与公共视觉分开组织。目标 Gradle 边界为 `:app`、`:contracts`、`:vpn`、`:core-bridge`，按实际实现建立，Rust 位于 `native/`。跨模块契约、服务和 JNI 的依赖方向见 [技术架构](technical-architecture.md) 与 [目录边界 ADR](adr/0003-directory-boundaries.md)。先单进程，避免在网络正确性尚未证明时增加多进程同步成本。

UI 层消费不可变状态并发出用户意图，ViewModel 不直接持有 native handle 或 TUN fd。服务管理唯一运行状态，Rust bridge 绑定选定核心版本，异步事件带请求标识和会话 epoch，拒绝过期回调更新新会话。

验收分层：目录审计检查映射；JVM 测试验证纯状态与序列化；Compose 测试验证交互与语义；Rust/bridge 测试验证 ABI 和生命周期；设备测试验证 VPN、socket 与真实网络。任何一层的通过都不能替代另一层。

原型证据覆盖状态/DOM、导出结构、配置目录与文档完整性。P00 已另行验证实验 APK、JNI 解析、有限 TUN 观察和受控端到端通信，精确范围见 P00 最终报告；正式产品、浏览器像素渲染、系统 Monet 及范围外网络行为仍待验收。
