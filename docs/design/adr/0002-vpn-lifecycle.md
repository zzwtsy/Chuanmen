# ADR 0002：VPN 生命周期与地址真实性

状态：候选决定；P00-05 受控数据通路与 P00-06 有限地址/平台参数场景已验证，生产生命周期尚未验证。

已实测边界：Xiaomi API 36 上，平台探针和六文件原生实验补丁分别完成 20 轮 TUN 建立/关闭与核心借用终止；随后 TCP/UDP 各连续 20 次真实回包，以及另 20 轮连接中启停通过。实际拒绝系统授权、系统撤销与关闭全部物理网络分别记录；撤销和断网后的本应用通知数由 `NotificationManager.getActiveNotifications` 实读为 0。证据见 [P00-05](../../verification/p00/reports/p00-05-datapath.md)。断网后停止由实验工作线程显式执行，不证明核心自动断网恢复；自动地址与有限 TUN 替换见后文 P00-06，生产会话代次仍未验证。

## 会话与状态

服务持有唯一真实会话；页面选择的 `profileId`、本地 `localDisplayName` 与运行会话身份分别保存。页面切换和本地改名不发送连接命令。草稿、已保存配置和已确认应用快照分别建模；解析成功、保存成功和 fd 入队均不更新“已应用”。

状态候选依次为授权准备、核心启动、协商地址、建立 TUN、确认核心安装、验证数据通路、运行、停止与失败。每个异步结果带会话编号；旧会话结果只供诊断，不能写入当前地址或连接状态。demo 和 real 必须显式选择，real 失败保持失败。

原生实验已区分 `setTunFd` 入队、补丁 `installed`、核心 peer 在线和应用真实回包。首两次实验虽有 peer 与路由，TCP 仍超时，报告保持失败；正式状态机也必须保留这一判据。阻塞 native 停止调用由工作线程执行；当前服务实验代码尚未完成生产会话协调器，不能把 `onRevoke` / `onDestroy` 的同步兜底称为完整串行实现。

网络切换后的实测还发现：native 已安装 TUN 时，系统尚未把测试应用流量路由到 VPN。实验增加实际 `ConnectivityManager` VPN 路由就绪和核心虚拟路由读回，再发业务请求；这一等待不代替真实回包判据。复现失败与成功均保留，未通过重试补齐连续成功数量。

## 地址与重建

静态地址以核心实际读回和 Android TUN 观测交叉核对；自动地址以协商结果为准。草稿地址不冒充实际地址。[P00-06](../../verification/p00/reports/p00-06-address.md) 实读 DHCP 从无地址变为 10.222.0.2/24，再建立同地址 TUN 并取得真实回包。JNI 事件列表会在多份 DTO 中重复，尚无已证实的稳定投递协议；宿主采用会话代次绑定轮询与参数差异比较，不承诺任意核心热更新。

Android `VpnService.Builder` 在 `establish` 时提交地址、路由和 DNS。需要重建时，先验证新参数，在同一会话协调器内建立替代 TUN，等待核心安装及旧借用终止，再关闭旧 PFD；旧、新 fd 的交接顺序和通信中断窗口必须实测。静态地址、DHCP、路由、DNS、MTU 分别形成结果，不能由单个字段推导全部热更新能力。

同核心平台 MTU/DNS/路由的三次替换已实际确认新安装、旧释放和 PFD 关闭；顺序采样成功间隔约 68–90 ms，不能当成连续测量的丢包窗口。核心地址/flags.mtu 改动采用完整重连。DNS 仅有系统参数读回，解析服务仍未验收；旧真实 JNI 快照的代次过滤只属于实验宿主，不扩大为上游 callback 或生产会话实现。

IPv6 底层传输、虚拟 IPv6 与非组网 IPv6 策略分别实验。平台探针只添加合成 IPv4 地址及测试路由，没有 DNS、IPv6 或默认出口验收。

## 授权、前台服务与终止

`prepare` 返回授权请求时由用户选择；拒绝后不启动 VPN。撤销可能在非主线程进入 `onRevoke`，通过统一关闭路径禁止新任务、取消核心并等待借用结束，再释放平台资源；用户主动断开后不自动重连。`protect` 不关闭 socket，也不证明已经绑定指定网络；指定物理网络需要另行验证 `Network.bindSocket` 与底层网络更新。依据：[VpnService 平台文档](https://developer.android.com/reference/android/net/VpnService)。

API 34+ 的平台探针声明 `systemExempted` 前台服务类型及权限；官方资格包含已在系统 VPN 设置中配置的 VPN 应用。运行时资格失败必须保留实际异常，不能降级成模拟启动。依据：[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)。正式 Android 生命周期和商店分发仍需项目版本对应的验证。

资源停止契约见 [ADR 0001](0001-native-host-boundary.md)。超时和失败不能覆盖为断开成功；记录仍持有的资源并阻止重复启动。进程死亡后的恢复策略和 always-on / lockdown 行为需要另行受控实验，不从 instrumentation 中推断。
