# P04 · 总览、设备、实时流量与双来源日志

> 状态：待实施。预计 2–3 周。所有运行数据必须有来源和会话归属；演示数据只能出现在明确标记的 demo 场景。

## 1. 目标

让用户用一页判断当前网络是否运行、是否有设备、是否有本机业务流量。
设备详情集中呈现必要诊断信息，日志有统一入口且可读。
把已冻结交互变成真实 Android 页面，并保持 Material 3 Expressive 与动态配色的一致性。

## 2. 前置门槛

- P02 已提供可靠运行状态、设备和统计接口；暂缺字段有可表达的 unavailable。
- P03 的 profileId、独立名称、保存修订和运行快照已统一。
- P01 的共用组件、主题、导航和 demo fixture 可用。
- 已阅读最新配置原型；不沿用旧版的流量详情页和设备相关日志入口。
- 上游统计的范围、方向、单位、刷新和重置条件已写成口径表。

## 3. 分任务

### P04-01 · 建立可观测数据契约

1. 定义 PeerSnapshot、LocalTrafficCounters、ProbeResult 和 LogRecord。
2. 所有快照带 sessionId、来源时间与新鲜度，避免不同会话混合。
3. 明确每个值来自核心状态、TUN 计数、主动探测还是本地计算。
4. 缺失值用未知 / 暂不可用，离线旧值用上次记录，不能一律显示 0。
5. 核心日志只作日志，不能依赖非稳定文字匹配推导正式连接状态。
6. 为 NAT、版本、计数与探测口径准备真实采样和确定性 fixture。
7. 差异表列出桥缺失字段与补齐任务，不用随机值填充详情。

### P04-02 · 合并首页虚拟网络信息

1. 在虚拟网络卡片展示本地配置名、运行状态、真实虚拟 IP。
2. 合并在线设备数与直连 / 中继摘要，明确设备数是否包含本机。
3. 点击设备摘要进入设备主页面，不创建额外“在线设备详情”页面。
4. 连接主按钮反映当前实际运行网络，查看其他配置不会自动切换。
5. IP 使用共用图标复制组件，无地址时不给出可复制的假地址。
6. 卡片状态区分运行、等待设备、重连、断开和失败。
7. 移除首页独立在线设备卡及流量范围配置入口。

### P04-03 · 实现真实 TUN 计量

1. 上传统计成功从 TUN 读取的出站 IP 字节，下载统计成功写入 TUN 的入站 IP 字节。
2. 在真正拥有该数据路径的一侧计数，避免 Java / Rust 双侧重复累加。
3. 计数范围是本机 VPN 流量，含经过该路径的 IP 包，不等于应用有效载荷。
4. EasyTier 保活、仅核心控制消息和第三方中继流量不混入本机图表。
5. 两次同会话累计值之差除以单调时钟间隔，计算当前速率。
6. 处理计数重置、回绕、零间隔、超时和过期采样；异常记录为空而非尖峰。
7. 选中未运行的网络时展示未运行状态，不能拿当前 A 网络数据填到 B。
8. 对端链路计数与 TUN 计数分开标注，不承诺它们相加严格相等。

### P04-04 · 实现固定 60 秒趋势图

1. 首页直接展示上行 / 下行当前速率、单位及两条曲线。
2. 固定最近 60 秒窗口，建议每秒采样，使用有界环形缓冲。
3. 图表是展示组件，不支持拖动读点、缩放、时间切换、暂停或回看。
4. 不建立流量详情页，不增加手势覆盖层或可开关图例。
5. 真实 0 速率画在零线；采样缺失断线或留白，不填造数据。
6. 纵轴缩放有节制并显示单位，不把几字节噪声夸大为显著流量。
7. 开始连接时允许逐步积累样本，不补齐 60 秒虚构历史。
8. 仅可见页面重绘图表；回到前台后的断档保留，不从后台高速补动画。
9. 屏幕阅读器读取当前上下行和运行状态，不逐点朗读每秒变化。

### P04-05 · 集中设备信息与操作

1. 设备列表以名称、虚拟 IP、连接方式和必要质量摘要呈现。
2. 卡片支持少量同页展开；更多信息集中到一个设备详情页。
3. 详情包括 NAT 类型、EasyTier 版本、发送 / 接收字节和包计数。
4. 丢包必须标注来源与观察窗口，例如探测丢包，不能含糊写业务丢包。
5. UDP / TCP NAT 能分别取得时分别显示；无法取得时保留明确未知状态。
6. 直连、中继、对端离线和过时数据用语清楚，不只依赖颜色。
7. 列表和详情均不提供相关日志按钮，日志统一从日志主页面进入。
8. 详情 IP 使用与首页相同组件；复制成功使用短暂反馈，不改变布局。
9. Android 已提供复制反馈时避免叠加第二条提示，旧系统使用短 Toast。

### P04-06 · 实现按需连接探测

1. “检查连接”是明确用户动作，目标限当前查看且已知的虚拟对端。
2. 选择可证明的探测方式，说明是否依赖对端响应、ICMP 或核心 RPC。
3. 展示探测时间、成功次数、往返延迟和丢包分母。
4. 超时不直接认定设备离线；区分控制面可见与业务路径不响应。
5. 取消、离页与会话切换停止旧探测结果更新。
6. 并发探测有上限，不能在滚动设备列表时自动启动大量请求。
7. 诊断文案给就近可操作入口，不重新加入设备相关日志跳转。

### P04-07 · 建立双来源日志管道

1. 核心日志和 App 日志保留不同来源标记，统一时间、级别和会话上下文。
2. App 日志记录授权、生命周期、配置应用和桥错误，不记录每个业务包正文。
3. 核心日志采用固定版本支持的可控采集方式，禁止默认导出无限 debug。
4. 写入前脱敏网络密码、私钥、令牌及完整配置文本。
5. 设置有界缓冲、轮转、磁盘上限和丢弃计数，慢 UI 不阻塞核心。
6. 按来源、级别、关键字和会话筛选，UI 列表虚拟化。
7. 正在读历史时不被新日志拉回底部；提供明确恢复跟随入口。
8. 采集级别与查看过滤分开，修改过滤不冒充改变核心采集。
9. 日志页管理两种日志的设置；配置页不塞进程级日志参数。
10. 沿用 [P02 控制面事件](p02-vpn-core.md#p02-08--构建真实诊断证据)的有界、脱敏记录，保留单调相对时间、会话代次、操作身份和配置修订；格式与消费接口稳定后，将真实故障转为控制器回归 fixture。
11. 故障重放先覆盖启动中撤销、停止后晚到回调和应用回执丢失，用行为断言核对收束、代次隔离及结果未知语义。

### P04-08 · 完成原生体验核对

1. 核对底部导航、返回、对话框、键盘与屏幕旋转，不增加额外任务层级。
2. 总览、设备、配置、日志共享同一配置选择和会话归属语言。
3. 主题切换与系统动态色不破坏曲线、错误和连接状态的可辨性。
4. 确认当前数值、累计数值、对端统计和本地 TUN 图表单位一致且不混淆。
5. 用真实与 fake 两套相同场景检查界面，不用 demo 验收替代实机采样。
6. 把原型有而原生暂缺的能力列清单，进入 P05/P06，不隐瞒差异。

## 5. 依赖与并行边界

- 设备、流量、日志 UI 可并行，统计口径先统一再分别绘制。
- 图表可用固定 fixture 开发；真实计数接线由 P02 所有权负责人审核。
- 日志落盘和 UI 过滤分离，不让 UI 线程承担文件轮转。
- NAT / 版本缺失时补桥证据，不让 UI 私自解析核心内部对象。
- P05 高级流量可能改变统计组成，必须保持本机 TUN 口径不变。

## 6. 验证与明确通过标准

| 场景 | 通过标准 |
|---|---|
| 图表范围 | 固定 60 秒，无详情、拖动读点、时间选择和暂停入口 |
| 数据归属 | 切配置、重连和计数重置后没有旧曲线、负值或异常尖峰 |
| 流量真实性 | 受控本机传输时计数变化；纯保活或第三方中继不造成业务曲线 |
| 空闲 / 缺采样 | 真实零值与无数据在内部语义及展示上可区分 |
| 页面归并 | 首页只有一个网络 / 在线设备信息主体，无额外设备统计页 |
| 设备详情 | NAT、版本、收发、丢包各有真实来源或明确不可用原因 |
| 复制 | 两处组件一致、成功反馈短暂，Android 系统反馈不重复 |
| 日志阅读 | 新日志到达不打断历史阅读，恢复跟随明确可用 |
| 日志边界 | 限定容量后可持续运行，丢弃可解释，秘密不进入导出样例 |
| 故障重放 | 稳定事件格式保留顺序和操作归属，脱敏 fixture 能复现启动中撤销、停止后晚到回调和应用回执丢失，重放不访问真实秘密或业务包正文 |
| 无障碍 | 图表不每秒抢播，主要操作可通过 TalkBack 和大字体完成 |

性能按 P00 固定设备 / 场景和 P06 门槛评估，不凭曲线“很顺”判定。
流量有变化只说明计量路径有数据，不能证明所有配置或目标应用都已可达。

## 7. 失败回退与本阶段不做

- 指标无可靠来源时显示未知并补桥，不以 0 或估计值填充。
- 探测不可达时保留真实原因与时间，不自动判定 NAT 类型。
- 日志写入过载时有界丢弃并记数，不能阻塞网络包处理。
- 暂不做长期流量分析、按时间回放、逐应用流量归因或设备图表详情。
- 不因“想确认生效”而把持续主动探测、通知动画或假曲线作为常驻行为。
- 不恢复设备相关日志入口；全局日志可按会话过滤。
