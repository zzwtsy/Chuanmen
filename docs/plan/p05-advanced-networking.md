# P05 · 全部高级网络能力与导入导出

> 状态：待实施。预计 3–4 周。目标是让既定完整配置范围形成实机闭环；字段能保存不等于网络能力已实现。

## 1. 目标

完成官网配置助手范围内适用于本客户端的高级能力，并保留清晰的平台边界。
完成 TOML 与本地配置包的用户级导入、预览、迁移和导出。
本阶段结束后，每个应支持编辑单元都有真实行为证据或明确阻塞，不用删除低频功能制造完成率。

## 2. 前置门槛

- P00 高级能力探针与风险表可追踪，核心版本及构建开关没有随意改变。
- P02 生命周期、TUN 协调、protect 与受控重连已稳定。
- P03 目录、codec、字段校验和共享草稿可用。
- P04 能观察真实设备、业务流量和脱敏日志。
- 准备受控局域网主机、出口节点、WireGuard 客户端与不同 NAT 条件。
- 高级测试只在授权环境执行，测试端口、ACL 和凭据有清理步骤。

## 3. 能力覆盖矩阵

下表是实施分组，精确字段类型与来源以冻结目录和固定核心为准。

| 能力组 | 主要核心字段 | 验证结果 |
|---|---|---|
| 基础身份 | network_identity、hostname、dhcp、ipv4 | 复核 P03/P02 真正运行，保持本地名称独立 |
| 监听与公布 | listeners、mapped_listeners、peer | 监听建立、外部可达、关闭与空列表语义 |
| P2P 行为 | disable_p2p、p2p_only、lazy_p2p、need_p2p | 连接路径符合策略，状态真实 |
| 建链手段 | UDP/TCP/对称 NAT 打洞、UPnP 开关 | 在可控网络下验证启停作用 |
| 路由与出口 | routes、exit_nodes、proxy_network、enable_exit_node | 接收路由、使用出口与提供出口分别验证 |
| 本地服务 | socks5_proxy、port_forward、vpn_portal_config | 真实绑定、受控访问、冲突及资源释放 |
| 安全策略 | enable_encryption、private_mode、acl | 正向与拒绝路径，秘密不入日志 |
| 性能与中继 | latency_first、mtu、instance_recv_bps_limit、relay_network_whitelist、relay_all_peer_rpc | 可观察行为与边界数值 |
| 传输增强 | enable_kcp_proxy、disable_kcp_input、enable_quic_proxy、disable_quic_input | 代理与接入分别验证 |
| DNS / IPv6 | enable_ipv6、accept_dns 与 Android 对应策略 | 底层、虚拟地址及旁路 / 阻断层次分开 |
| Android 策略 | 7 个独立 Android 编辑单元 | 应用范围、互联网路由、DNS、IPv6、自动重连闭环 |

flags 前缀在表中部分省略以便阅读；实现仍使用稳定完整 key。
不额外扩张到本次线上助手没有的 STUN 编辑、加密算法选择或远程管理。

## 4. 分任务

### P05-01 · 将能力矩阵接入完整配置

1. 为每项填写已实现、验证设备、限制、字段生效方式和证据路径。
2. 区分编译缺失、宿主未适配、当前环境不可达与用户输入错误。
3. P00 未通过的 Portal / 用户态出口等任务先解决桥或宿主缺口。
4. 只有确定不适用或平台托管的项目隐藏；低频功能不能因此消失。
5. 未完成能力保留明确缺口，不以禁用开关占位后称完整版本已完成。
6. ipv6_public_addr_auto 等仅因尚未适配而隐藏的项，按 P00 结论补实现、做实机验证并恢复表单 / 搜索。
7. 原型 37 + 7 目录保持历史快照；原生能力目录独立版本化，不把 44 当永久数量门槛。
8. 若项目需发布范围缩减，写清对用户承诺的变化并进入退出评审。

### P05-02 · 完成连接、监听与建链策略

1. 完成 peer、listeners、mapped_listeners 的多条编辑与无损保存。
2. 区分省略默认监听、显式不监听和自定义监听。
3. 验证新增监听、停止监听、端口冲突和底层 socket 保护。
4. 对普通 P2P、仅直连通信、懒建立和要求对端建立验证实际路径。
5. 校验互斥组合，错误定位到具体字段，而不是连接时笼统失败。
6. UDP / TCP / 对称 NAT 打洞和 UPnP 用可控制对端与网络验证。
7. 无法控制 NAT 的公网实验只作补充，不能作为唯一回归依据。

### P05-03 · 完成路由、子网与出口

1. 完成手动路由、退出节点和分享子网的结构化编辑。
2. 验证使用远端出口与允许本机作为出口是不同操作。
3. 子网代理采用已证实的用户态路径，不能偷偷依赖 Linux 内核转发。
4. 对私网目标、冲突路由、重叠 CIDR 和无效下一跳提供明确校验。
5. 验证控制面宣告与 Android 实际 TUN 路由一致。
6. 撤销路由或退出网络后，旧路由和代理连接必须清理。
7. 默认路由变化通过 P02 重建流程应用，不能让“仅保存”影响当前流量。

### P05-04 · 完成本地服务与 WireGuard Portal

1. 对 SOCKS5 验证绑定地址、端口冲突和外部暴露范围。
2. 对端口转发分别验证支持的协议、来源、目标与停止释放。
3. 对 WireGuard Portal 核对官网子字段与当前核心对象的转换。
4. 证明外部 WireGuard 客户端实际完成握手与受控目标通信。
5. Portal 配置生成必须使用真实能力和密钥，不能生成示例配置冒充可用。
6. 密钥只在需要时展示 / 导出，日志和诊断默认脱敏。
7. 明确共享会把什么地址或端口开放给谁，用户能在启用前判断影响。
8. 若桥、宿主或 Android 网络限制未解决，此能力判失败并保留修复任务。
9. 不用“服务对象创建成功”代替外部客户端实际访问。

### P05-05 · 完成安全、性能与传输增强

1. 通信加密默认开启，关闭属于显式用户决定且说明实际影响。
2. ACL 用结构化编辑或受控文本编辑加核心解析，支持定位无效规则。
3. 对 private_mode、ACL、中继白名单分别做允许与拒绝用例。
4. MTU 用不同包大小验证，不只检查数字落在输入范围。
5. 接收限速验证单位、无上限值和实际限速趋势，保留 u64 精度。
6. latency_first 与中继 RPC 转发使用可控拓扑观察实际路由选择。
7. KCP/QUIC 代理与允许接入是两组不同开关，不能合并成一个“加速”开关。
8. 不虚构加速收益，记录相同设备 / 对端 / 网络条件下的实测变化。

### P05-06 · 完成 Android 路由与 DNS 策略

1. 验证 all、allowlist、denylist，处理空选择与已卸载应用。
2. 对 overlay-only 与经指定出口的互联网范围做目标可达性测试。
3. VPN 系统允许 / 拒绝列表互斥，修改时明确需要新建接口。
4. 对系统 DNS、自定义 DNS 和 MagicDNS 写出优先级及真实查询路径。
5. 区分 IPv6 底层传输、虚拟网络 IPv6 和非组网 IPv6 旁路 / 阻断。
6. 同时测试 IPv4 / IPv6，不能因为 IPv4 通过就声称 DNS / IPv6 无泄漏。
7. 对 Always-on 的阻断非 VPN 连接模式验证应用排除列表的实际后果。
8. 无法满足某策略时明确说明限制，不能静默旁路。
9. 自动重连只恢复既定运行目标，显式断开后不重连，也不连接仅查看的配置。

### P05-07 · 实现导入与兼容预览

1. 通过系统文档选择器读取 TOML 或本项目版本化配置包。
2. 解析前检查文件大小、编码和内容类型，不把配置当命令执行。
3. 显示本地名称、网络名称、敏感字段存在情况和平台差异。
4. 对未知字段、平台托管值和不支持项给出保留 / 应用差异。
5. 新建为默认导入行为，覆盖现有配置必须明确选择目标。
6. 导入不自动启动 VPN，也不隐式更改当前会话。
7. 错误指出字段或位置，保留用户选择与原件，不创建半份配置。
8. 对旧 schema 迁移后先预览，再写入原子存储。

### P05-08 · 实现导出、备份与迁移

1. EasyTier TOML 导出只使用核心配置语义，不写入 Android 私有字段。
2. 本项目配置包有独立 schema，包含本地名称与 Android 策略。
3. 默认使用脱敏导出；要包含密码或 Portal 密钥时明确告知内容范围。
4. 完整备份使用具备完整性保护的成熟加密方案，不自创加密格式。
5. 通过系统文档接口保存，成功反馈必须以写入完成为依据。
6. 导入导出 round-trip 同时核对已知值、未知值和本地元数据。
7. 对损坏、截断、错误密码和未来版本包保留可理解错误。
8. 日志导出提供日期 / 会话范围，默认脱敏，不把配置全量附进去。

## 6. 依赖与并行边界

- 连接策略、服务能力和导入导出可分线并行，统一 codec 与能力表禁止分叉。
- native 功能补丁归同一负责人维护，避免多线同时升级核心。
- DNS / IPv6 / 应用范围共用 TUN 协调器，不能各自独立 establish 接口。
- Portal 可单独验证，但停止、日志和密钥生命周期要复用主会话规则。
- 新能力进入公开构建前必须完成对应真实对端用例。

## 7. 验证与明确通过标准

| 验证组 | 通过标准 |
|---|---|
| 目录闭合 | 每个可见项都有行为验证；隐藏项理由明确，未完成项有阻塞结论 |
| P2P / 监听 | 默认、省略、自定义与关闭语义真实，端口冲突可恢复 |
| 子网 / 出口 | 真机与受控远端完成正反向测试，撤销后无残留路由 |
| 本地服务 | 实际客户端可访问，停止释放端口；错误不导致整个 App 崩溃 |
| Portal | WireGuard 客户端真实握手和数据往返，密钥不进入普通日志 |
| ACL / 加密 | 允许与拒绝用例均通过，关闭加密不会被默认启用 |
| DNS / IPv6 | 每种声明支持的组合都有请求路径证据与无效配置处理 |
| Android 分流 | allow/deny互斥、空列表不误导、缺失应用可处理、跨网络隔离 |
| 导入导出 | round-trip 保留语义，秘密选择明确，导入不自动连接 |
| 高级异常 | 冲突、无权限、无依赖、未知字段不被静默删除或忽略 |

P05 的“通过”必须覆盖已承诺能力；只验证主路径不等于功能全面。
网络环境限制可记录为条件，但不能把核心缺实现写成环境问题。

## 8. 失败回退与本阶段不做

- 高级功能失败先复查固定核心、构建开关、宿主适配和网络环境四层。
- 无法无损表达的配置保留原件并停止覆盖，不把它转换成近似配置。
- 加密备份未完成时保留脱敏导出，不临时使用明文全量自动备份。
- 不新增官网范围以外的高级参数、Root 功能、账号体系或远程配置下发。
- 不将手机热点共享、内核级路由或系统全能代理作为免 Root 自然具备的能力。
- 产品范围要变更时记录为显式范围决策，不能直接删除未完成条目。
