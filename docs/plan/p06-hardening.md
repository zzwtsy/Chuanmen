# P06 · 系统可靠性、安全、性能与可访问性

> 状态：待实施。预计 2–3 周。将“可以使用”推进为“遇到常见系统变化仍可解释、可恢复、可控制”。

## 1. 目标

收敛 Android 系统生命周期、长时间运行、敏感数据与真实设备体验风险。
补齐通知、Always-on 系统入口和可选快捷开关，使客户端融入 Android。
质量门槛以固定设备和可重现方法衡量，不以测试数量或覆盖率百分比代替结果。

## 2. 前置门槛

- P02 生命周期与真实数据面稳定，P03–P05 已具备对应用户流程。
- P00 已记录参考设备、网络场景及性能基线。
- P05 能力矩阵无未解释条目；未完成项已明确阻塞或正式调整范围。
- 有最低支持系统、主流系统、最新目标系统和至少两个 OEM 的测试安排。
- 阅读当前 [前台服务用户停止行为](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping)。
- 正式 targetSdk、前台服务声明和权限规则必须按发布时官方要求再核对。

## 3. 分任务

### P06-01 · 完成系统集成体验

1. 通知展示真实连接状态、本地配置名称和可用操作，点击回到对应网络。
2. 通知断开动作经过同一 SessionController，不能另写 Service 控制逻辑。
3. 断开后通知消失，失败 / 重连状态不继续显示“已连接”。
4. 在设置提供系统 VPN / Always-on 设置入口，说明当前配置归属。
5. Always-on 与阻断非 VPN 连接须经过真机验证后才声明支持。
6. 系统控制的模式下按平台规则处理断开操作，不能让 App 与系统反复争抢重连。
7. 快捷设置 Tile 作为 P1 体验项，复用上次明确选择的运行配置和状态源。
8. Tile / 通知不得跳过系统 VPN 授权，也不得连接仅在页面中查看的其他配置。
9. 未证明的 Always-on 支持明确关闭或说明限制，不能暗示后台永不掉线。

### P06-02 · 收敛重连与网络变化

1. 使用有限退避和抖动，分别记录网络不可用、认证错误和配置错误。
2. 用户明确断开时停止重试；网络恢复只恢复仍希望运行的目标。
3. 处理 Wi-Fi 到蜂窝、蜂窝到 Wi-Fi、飞行模式、门户网络与 DNS 变化。
4. 观察 VPN 网络时避免误将自己的接口当作底层物理网络。
5. 多个网络事件合并处理，不能重建多个 TUN 或并发启动核心。
6. 配置切换与系统切网同时发生时，最新用户意图优先且有明确 session 归属。
7. 长时间无对端与临时传输失败分开，不用无限重启核心掩盖原因。
8. 保留网络恢复后的业务可达性证据，不只统计“重连成功”事件。

### P06-03 · 验证进程与授权边界

1. 覆盖划掉最近任务、系统回收、用户停止前台服务、强行停止和系统撤销 VPN。
2. 不依赖所有退出都能收到回调；恢复时核对真实资源和持久化状态。
3. 显式用户停止不能被定时任务、广播或 WorkManager 绕过。
4. 对系统发起的受支持 Always-on 启动恢复保存配置，不恢复未保存草稿。
5. 无配置、配置损坏或解密失败时停止并提供可恢复入口。
6. 低内存、屏幕关闭与 Doze 下的行为在受控设备记录，不承诺绕开 OEM 管理。
7. 再次启动 App 时读取 Service 实际状态，不能根据上次页面缓存显示连接。
8. 用非生产测试包和设备验证系统行为，证据明确区分停止方式。

### P06-04 · 关闭敏感数据风险

1. 建立密码、私钥、网络标识、IP、应用列表和日志的分类与保留策略。
2. 核查敏感字段的静态加密、密钥失效与设备迁移行为。
3. 将系统备份 / 设备传输规则与加密模型对齐，避免密文迁走却无法解密。
4. 导出前预览包含什么，默认脱敏，密钥导出由明确用户动作触发。
5. 复制密码 / 私钥时使用敏感剪贴板标记；普通 IP 不当作密码处理。
6. 确认日志、崩溃记录、测试截图、CI 输出和 AI 上下文不含生产秘密。
7. 网络监听面、导出的组件、文件提供者与可变 PendingIntent 都有具体检查。
8. Debug 诊断入口不能进入公开 release，生产构建不携带测试凭据。
9. 检查依赖来源、核心补丁、许可证与原生崩溃符号保管。

### P06-05 · 建立资源与性能门槛

1. 固定参考手机、温度条件、对端和网络拓扑后重跑 P00 基线。
2. 分开测未连接、已连接空闲、前台图表、持续流量和高日志输入。
3. 观察 CPU、内存、fd、线程、唤醒、磁盘及电量，不只测峰值吞吐。
4. UI 不可见时停止不必要的曲线重绘与日志列表计算。
5. 日志有明确字节 / 时间上限，UI 队列有界，达到上限可解释地丢弃。
6. 对真实热点做优化，保持桥接口和计量语义不变。
7. 使用可重现的性能测试测冷启动和关键导航；按收益决定 Baseline Profile。
8. 同一条件下对比优化前后，保留原始样本与测试误差。
9. 不能用“更快”承诺未知网络吞吐，也不为小收益引入另一套数据面。

### P06-06 · 完成可访问性与适配

1. 在 TalkBack 下完成创建、命名、连接、复制、改配置、查看日志和断开。
2. 验证 200% 字体、较窄窗口、横屏、分屏和键盘出现时主要操作可达。
3. 触控目标按 48 dp 约定检查，图标有名称、状态和合理阅读顺序。
4. 错误不只靠颜色区分，输入错误可被辅助技术定位。
5. 浅色、深色和多组动态色中，正文、曲线与状态色达到约定对比度。
6. 尊重系统减少动画相关偏好，图表不依赖动画表达是否运行。
7. 边到边布局、系统栏、底部操作区和手势返回不互相遮挡。
8. 检查 [Android 复制反馈](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste)，避免系统与 App 重复提示。
9. 保持原型冻结的页面关系，不借适配增加一串设置子页。

### P06-07 · 完成长时间与组合回归

1. 在参考设备完成 24 小时运行，其中包含空闲、业务流量和日志轮转。
2. 在第二 OEM 完成至少 8 小时运行与一次受控切网。
3. 在固定条件下执行 100 轮连接 / 断开与 20 轮网络恢复。
4. 组合测试修改配置时切网、应用失败时离页、导入时进程终止。
5. 覆盖 IPv6、DNS、应用排除与 Always-on 的已声明支持组合。
6. 高级服务运行后退出、撤销授权或更新 App，检查端口与 fd 清理。
7. 记录每个失败的最小复现，不通过增加重试次数把失败变成绿色。
8. 执行失败复测针对原因与关联路径，避免无目的重跑整套测试。

### P06-08 · 建立发布前质量报告

1. 把需求、用例、设备证据与缺陷对应到稳定编号。
2. 区分单测、模拟器、真机、人工可访问性和长时间运行证据。
3. 未执行的用例标未执行，不能合并到通过数量。
4. 原生崩溃保留脱敏符号化信息，定位到 App / 核心 / 系统层。
5. 对允许带入 Beta 的问题写影响、绕行和复测条件。
6. 更新兼容矩阵、已知限制、操作文档与 AI 故障夹具。
7. 只有重复出现且流程稳定的工作才固化为 skill，普通规则留 AGENTS / 文档。

## 5. 依赖与并行边界

- 系统可靠性、安全审查、UI 适配可以并行，由同一冻结候选构建作为基线。
- 吞吐测试和耗电测试不能同时运行在同一台设备上互相污染数据。
- P05 原生补丁进入候选后才进行对应长期测试，不能测试旧核心后替换发布。
- 真机占用排期要写设备与时间，避免多个 AI 任务同时控制同一设备。
- P07 可并行准备发布资料，但不得冻结尚未经过本阶段的产物。

## 6. 验证与明确通过标准

以下为项目建议质量门槛，在 P00/P06 评审时冻结；它们不是平台保证。

| 项目 | 通过标准 |
|---|---|
| 长时间运行 | 参考设备 24 小时与第二 OEM 8 小时无 App 引入的崩溃 / ANR / 卡死 |
| 重复生命周期 | 100 轮开关无重复会话和持续 fd / 线程增长 |
| 切网 | 20 轮受控恢复结果可解释，手动断开后 0 次未经请求的自动连接 |
| 内存 | 暖机后无持续单调增长；超过既定容量的日志和采样被有界处理 |
| 性能回归 | 同基线场景的 CPU / 吞吐 / 时延若劣化超过 10%，必须解释并评审 |
| 安全 | 发布日志 / 导出默认样例 0 个秘密泄漏；无未处理高风险数据丢失问题 |
| 适配 | TalkBack 可完成关键任务，200% 字体无不可达主按钮 |
| 系统状态 | 页面、通知、Tile 与 Service 一致，撤销 / 停止后不显示运行 |
| 已知缺陷 | 严重安全 / 数据问题及关键任务阻断缺陷为 0；其余有明确影响和负责人 |

10% 是触发调查的相对变化，不是对不同手机性能作同一绝对承诺。
功耗只在同设备同条件作对照，并记录温度、信号和电池统计误差。

## 7. 失败回退与本阶段不做

- OEM 后台策略受限时提供具体系统入口，不能通过无意义保活绕过用户意图。
- Always-on 组合未证实时关闭对应支持声明，保留明确兼容问题。
- 原生升级引入回归时回退固定核心与补丁，保留数据 schema 兼容。
- 性能不达标先定位采样、日志、锁和包复制，不直接重写架构。
- 不添加广告、账号、云分析或默认上传诊断以解决观察不足。
- 不把“所有 Android 机型永不断线”作为产品承诺。
