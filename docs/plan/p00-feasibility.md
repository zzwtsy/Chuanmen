# P00 · 证据冻结与真机可行性

> 状态：verified（2026-10-12），M1 在约定范围通过。P00-01–08 已交付基线、固定版本与许可安排、配置解析、有限原生实验和真机度量；独立 AI 已在第二主机从空编译缓存完成记录中的构建流程，并复核既有真机证据，未重跑设备实验。范围仅当前 Xiaomi / Android 16 / arm64 / 4096 字节页、受控网络；其他能力继续按台账标为未验证。阶段退出记录已完成，P01/P02 尚未启动。实测边界见 [能力台账](../verification/p00/report.md)，结论见 [退出评审](../verification/p00/report.md#未验证项与停止条件)。

当前子任务状态与缺口见 [能力台账](../verification/p00/report.md)，版本和哈希见 [证据清单](../verification/p00/manifest.json)，可执行实验入口见 [受控实验手册](../verification/p00/reproduce/README.md)。独立复核的执行身份、授权依据与退出建议见 [复核记录](../verification/p00/reviews/independent-review.json)；该记录未声称用户最终退出批准，也未授予生产或分发批准。

P00 原实施范围为 `docs/verification/p00/`、[原生宿主边界 ADR](../design/adr/0001-native-host-boundary.md)、[VPN 生命周期 ADR](../design/adr/0002-vpn-lifecycle.md)、`experiments/android-vpn-smoke/`，以及本文件和路线图的 P00 状态。此处记录历史实施范围；后续修改以具体任务授权与 [验证规范](../development/verification.md) 为准。冻结仅覆盖所选证据和必要输入，不约束后续正常开发。

## 1. 目标

把“能画出来的客户端”转成“已经证明可在免 Root Android 上实现的客户端”。
冻结上游代码、官网表单来源和设备矩阵，验证最短真实数据通路。
阶段结束时必须能指出每个关键能力的证据、限制和负责人。

## 2. 前置门槛

- 已拿到本交付包内最新交互原型，确认它是模拟界面。
- 阅读总体设计、配置范围和 [核心证据](../research/android-core-evidence.md)。
- 准备一台可调试的 Android 真机和至少一个受控 EasyTier 对端。
- 第二台真机及不同 OEM 可在本阶段后半加入，不能全部由模拟器替代。
- 测试网络、账号、设备属于项目或已获授权；使用测试专用网络密码。
- 本包仍不含完成产品验收的 Android 工程；纯平台探针没有 EasyTier 数据通路。P00 另交付有真实数据通路的原生实验探针，按能力台账记录其版本、验证范围和未验证项。

## 3. 分任务

### P00-01 · 固定需求与验收基线

1. 为已确认体验分配稳定需求编号，并映射到 P03–P06 的测试。
2. 固定主导航、同页配置、设备详情和日志入口，避免实施时重新增页。
3. 固定“基础配置 / 完整配置”名称、本地重命名和条件出现的操作区。
4. 记录固定 60 秒流量窗，不提供拖动、时间切换或流量详情。
5. 将最新原型文件哈希写入证据清单；旧版只作历史参考。
6. 区分“设计冻结”“待实证能力”“未来候选”，禁止混用完成状态。

### P00-02 · 固定上游与工具链候选

1. 选择要嵌入的 EasyTier tag 或 commit，记录完整 SHA，不能仅写 main。
2. 记录 Rust、NDK、JDK、Gradle、AGP、Kotlin 和 Compose 的候选版本。
3. 检查核心、依赖及复用代码的许可证和分发义务，交由发布负责人复核。
4. 列出 arm64 真机与 x86_64 调试需要的 ABI；额外 ABI 根据用户范围决定。
5. 验证当前 Google Play / Android 平台要求，再决定 minSdk 与 targetSdk。
6. 本阶段只锁定可重现候选，不用“最新”代替精确版本。

### P00-03 · 冻结配置映射证据

1. 保存官网部署入口和实际资源的 URL、抓取时间、SHA-256。
2. 以本包目录的 37 个核心编辑单元与 7 个 Android 编辑单元为历史起点，不把数量永久锁死。
3. 对每个字段核对类型、缺省、空值、启用条件和核心配置键。
4. 记录官网负向开关与核心正向字段的转换，不能直接复制布尔值。
5. 分别标记“官网有 UI”“核心能解析”“Android 已验证”。
6. 重审快照中的 8 个隐藏项，分别记录平台托管、产品模式或当前未适配，不能统一写不支持。
7. Portal 子字段、ACL、路由和列表使用真实核心解析器做最小样例。
8. 以部署文件哈希作为证据，不把另一个仓库主干当成线上版本。
9. 单独复核 ipv6_public_addr_auto：快照隐藏理由是尚未适配，不是 Android 永久不适用。
10. 为暂未适配但适用的项写 P05 修复、实证和恢复表单路径，独立维护原生能力台账。

### P00-04 · 核验原生桥边界

1. 在固定核心版本中定位 native host、平台回调和 TUN 接入代码。
2. 查明可复用的是内部接口、公开 API 还是需项目自有适配层。
3. 记录启动、停止、配置解析、统计、设备和日志的实际调用位置。
4. 查明文件描述符的借用、复制、转移与关闭责任，画出一份所有权表。
5. 验证回调线程、异步取消、错误传递和 Rust panic 的处理边界。
6. 拟定项目自有 Engine 接口，注明它不是 EasyTier 官方 SDK。
7. 复核 setTunFd 返回是否仅代表入队，及借用 fd 的 close_fd_on_drop 策略。
8. 比较固定 tag 与主干的 RPC / socket protector 暴露差异，不能跨版本套用调用名。
9. 若需上游补丁，记录最小补丁、升级冲突点和替代路径。

### P00-05 · 证明免 Root 双向数据通路

1. 创建一次性最小实验 App，获取系统 VPN 授权。
2. 将底层传输 socket 接到经过证实的 protect / 网络绑定路径。
3. 根据已协商地址建立 Android TUN，再将 fd 按所有权契约交给核心。
4. 从真机测试应用向受控对端发 TCP 请求和 UDP 回显。
5. 对端回包必须真实抵达测试应用；仅有“peer 在线”不算通过。
6. 抓取受控环境的包计数或对端记录，证明流量走指定虚拟网络。
7. 断开后确认 fd、socket、线程和前台通知被释放。
8. 用一次拒绝授权、一次撤销 VPN 和一次无网络验证错误路径。

### P00-06 · 地址与路由变化实验

1. 分别使用静态 IPv4 和核心自动分配地址连接。
2. 查明何时能取得地址、路由和 DNS，避免 UI 先显示草稿值。
3. 观察路由变更能否由核心事件稳定提供，记录事件缺失的处理方案。
4. 验证 Android TUN 需要重建的情形及连接中断窗口。
5. 测试旧连接回调迟到，确认不会覆盖新 session 的地址。
6. 不承诺任意字段热更新；输出逐类“可热改 / 需重连 / 未知”表。
7. 同时记录 IPv6 底层传输、虚拟 IPv6 和非组网 IPv6 策略的区别。

### P00-07 · 高级能力风险探针

1. 针对监听、公布地址、打洞和中继，记录核心构建开关与实机入口。
2. 为子网代理、本机出口、SOCKS5、端口转发、WireGuard Portal 各建探针。
3. 先证明服务能绑定、对端能到达且停止能释放，再进入 P05 完整实现。
4. 明确哪些依赖用户态协议栈，哪些需要当前客户端尚未提供的宿主能力。
5. 记录 Wi-Fi、蜂窝网络、NAT 和 Android 限制，不能把端口不可达误作 UI 错误。
6. 尚未通过的能力进入 P05 阻塞清单，保留实施任务与验证条件。
7. 不因为低频就删除官网已有项目，也不把未验证项目标为已支持。

### P00-08 · 制定度量与决策

1. 在固定真机记录连接时间、稳定传输速率、CPU、内存和空闲耗电基线。
2. 建立每次实验使用相同场景和采样时长的说明。
3. 决定第一版发布渠道、支持设备范围及不提供 Root 模式的边界。
4. 记录选中网络与实际运行网络分离、多配置保存而单会话运行的约束。
5. 为无法证明的关键链路给出有截止时间的补证任务。
6. 召开退出评审：通过、带明确阻塞进入并行准备，或暂停原生主线。

## 5. 依赖与并行边界

- P00-01、02、03 可并行，只共享冻结清单，不同时改同一证据文件。
- P00-04 完成后才推进 P00-05，fd 与 socket 责任不清时不写完整业务桥。
- P00-06 依赖基本连通；P00-07 可在基本连通后并行做小探针。
- P01 文档和构建草案可并行，依赖版本必须等 P00-02 决定后落地。
- P02 不能以“预计接口存在”开工；至少需要 P00-04、05 的通过证据。
- 原型 UI 调整不能作为解决底层数据通路阻塞的替代任务。

## 6. 验证与明确通过标准

| 验证 | 通过标准 |
|---|---|
| 可重现构建 | 另一名协作者按记录在干净环境构建出相同源码版本的实验 APK |
| 双向连通 | 一台真机完成 TCP 请求与 UDP 回显，各连续 20 次无错误 |
| 地址真实性 | UI / 桥读到的地址与实际 TUN / 对端观测一致 |
| 回环防护 | 底层传输 socket 不再次进入自己的 TUN，受控抓包或计数可证明 |
| 关闭资源 | 连续启动停止 20 轮，无残留会话；fd / 线程数量不持续增长 |
| 撤销授权 | 撤销后停止运行与通知，不无限自动重试或显示仍已连接 |
| 范围闭合 | 快照 44 个编辑单元与重审恢复项都有映射状态；8 个隐藏项均已重新判断 |
| 未知接口 | 每项未知均有负责人、下一次实验与停止条件，不能填“基本可用” |

这些数字是项目建议门槛；P00 可基于设备基线修改，并保留修改理由。
若还不能得到可信的 fd 或路由证据，P02 的启动门槛不通过。

## 7. 失败回退与本阶段不做

- 上游宿主不可直接复用：实现最薄适配层，并保留补丁清单，不重写 P2P 协议。
- 若特定 ABI 失败：先维持已验证 ABI，明确发布影响，再决定修复范围。
- 高级功能失败：保留问题与 P05 入口，不能通过删字段使能力矩阵“全绿”。
- IPv6 不完整：明确已支持的层次，不能宣称全量 IPv6 或无泄漏。
- 本阶段不实现完整 UI、生产数据库、完整 ACL 编辑器或自动更新器。
- 不下载并执行来源未知的诊断脚本，不把真实密码写进证据包。
