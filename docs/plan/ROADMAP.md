# Chuanmen 路线图

版本：2026-10-23。本文是阶段状态、实施顺序和验收范围的唯一维护来源。目标是基于 EasyTier 的原生 Android 客户端；目录以 [ADR 0005](../design/adr/0005-single-app.md) 为准，命令以 [开发环境](../development/setup.md) 为准。

## 1. 交付目标与阶段顺序

实施基线为 `main` 的 `8d4ade327963f4eed34a315dd735953d63d63dff`；[CI 39802191239](https://github.com/zzwtsy/Chuanmen/actions/runs/39802191239) 的 static、android 和 quality-gate 均通过。当前代码仍使用受控内存配置；本文中的持久化、完整编辑和新增系统能力是待实施交付物。

2026-10-23 范围决定：取消结构精简的设备补验及 P03–P07 全部设备验收。取消范围包括模拟器/真机执行、完整设备矩阵、release 冒烟、设备安装升级、长时运行、实测功耗、TalkBack 人工操作和 16 KB runtime。既有设备测试源码、工具和历史结果保留；androidTest APK 继续编译，不安装或执行。取消的项目不列为待补任务，也不改记通过。

原八阶段 15–22 工程周、含缓冲 18–27 自然周是历史估算，不再作为剩余排期。新计划按任务依赖和退出条件推进；任务开始时根据实际差异估算工程时间，外部签名/发布等待单列，不填写没有依据的固定总工期。

## 3. 优先级与范围管理

P0 为正确性：保存不暗中应用、本地名称独立、用户意图与会话归属正确、失败不丢数据、停止结果未知时不复用资源、秘密不进入日志。P1 为完整日常能力：全部适用目录、设备详情、日志、导入导出、系统入口。P2 为需要额外依据的扩展：多进程、更多 ABI、大规模模块化与通用框架，不在本轮增加。

已确定的产品决定：

- 免 Root、单个活动 VpnService、本地管理多个配置，正式构建始终使用真实核心。
- P03 首批 10 项；P05 首次接入其余 34 项，并扩展 peer 成员/协议及既有 Android 策略。表单与能力同批接入，未实现项留在内部台账，不以可操作占位冒充完成。
- 仅持久化已保存配置；草稿切页/旋转保留，进程退出丢弃，敏感输入不进入系统保存状态。
- P06 在 API 29+ 实现并启用 Always-on；API 24–28 仍关闭该元数据，不提供 Direct Boot 连接。实现不构成设备验证。
- P07 仅准备 GitHub APK，不安排 Play/AAB、设备 Beta 测试或测试者招募；签名密钥访问、tag、上传及发布独立授权。
- 不建设账号、云同步、管理后台、Root 转发、并行 VPN 或 App 内 AI。

## 4. 任务与接口交接

每个任务必须逐项写明开始条件、现有/拟改文件或接口、按顺序执行的动作、失败后的数据/会话状态，以及“输入→操作→输出”的完成断言。任务号只用于排序和追踪，不能用“完成 P03/P04”代替所需接口。需要源码调查的事项列出查找对象、必须记录的事实及不同结果对应的动作。沿用阶段任务编号；P04 保留原 01–08 编号，计量和图表任务复用已有实现。P03-07 只承接现有策略，原全量应用名单与 DNS/IPv6 选择移至 P05-06。

共享契约按 P03 的接口表先落实：仓库负责持久化，配置功能独占草稿，Service 独占会话与采样。共享 lib 不依赖 features；不再创建旧 contracts/core-bridge/vpn Gradle 模块。原生 DTO 留在桥边界，所有新字段必须有来源和缺失语义。

同阶段按文件列出的执行顺序推进；P03 为 01 → 03 → 02 → 04 → 05 → 06 → 07 → 08，先提供文档 codec 再落盘；P05 为 01 → 02 → 03 → 06 → 04 → 05 → 07 → 08，先交付平台策略再接本地服务。不能仅按任务编号推断依赖顺序。每项实施完成后按 Git 工作流形成可审阅变更，提交/PR 动作仍遵循用户授权。需要并行时另行划分文件所有权；本计划不自动启动多代理。P07 文案可复用前面阶段的结果，但最终产物资料必须绑定最后候选。

## 5. 工程验收与决策规则

文档职责固定：路线图维护阶段状态和顺序；阶段文件维护具体任务断言；技术架构维护共享接口/数据约束；能力台账维护字段归属和实现证据；setup 维护可执行命令。若这些文件给出互相矛盾的规则，先修改冲突处再继续实施，不让执行者任选一处。

计划更新本身只需文档/JSON/目录/隐私检查，不运行产品构建或设备实验；开始 P03 代码后按各任务风险运行相关测试，阶段退出再运行完整工程组合。

允许的验证层次为静态审查、目录/隐私检查、Python 回归、JVM/Compose、宿主 Rust、APK 构建及 ABI/JNI/16 KB 静态检查。测试中的替身只证明对应模型和调用契约；本机 loopback 的宿主测试不证明 Android 网络效果。不新增设备实验，不以模拟器代替被取消的真机验收。

- 每次变更先运行受影响检查；阶段退出运行 [工程检查组合](../development/setup.md#工程阶段检查组合)。设备测试源码参与编译，不参与执行。
- 不删除断言、关闭检查或刷新基线掩盖失败；失败阻止对应工程任务完成。
- 核心和 Android 策略统一受控重连，本轮不新增热应用白名单。固定核心来源与工具链不顺带升级。
- 保存模型、版本迁移、原生接口或秘密边界变化同步契约和回归；普通测试产物留 build，不生成阶段实验包。
- 适用能力存在实现阻塞时，保留字段、原因和任务状态，不能为完成阶段静默缩减范围。
- 外部签名或发布未获授权时停在准备包，不将未授权动作算作已执行。

## 6. 进度如何计算

状态采用 `planned / in_progress / paused / blocked / verified`。规划完成不等于实现完成，已有部分代码不等于完整字段验收。`planned` 表示尚未开始；`in_progress` 表示已开始但断言尚未全部满足；`blocked` 必须记录缺失接口/依赖、已查证据及继续条件，不能用它表示普通待办；`verified（工程范围）` 要求该阶段每个任务断言和完整工程检查组合均通过。因范围决定取消的设备执行使用“未安排/未验证”，不伪装为失败或待补。

- **P00 / M1**：限定 Xiaomi API 36、arm64、4096 字节页及受控 IPv4 场景。历史第二主机空缓存复建与许可技术复核没有重复真机实验，生产补丁未获该实验批准。见 [P00 报告](../verification/p00/report.md)、[退出边界](../verification/p00/report.md#未验证项与停止条件)和[独立复核](../verification/p00/reviews/independent-review.json)。
- **P01**：原验收中的模块、demo 与主题预览属于历史装配。[退出评审](p01-foundation.md#p01-退出评审2026-10-14)与运行身份保持；现行目录按 ADR 0005，许可证为 AGPL-3.0-only。
- **P02 / M2**：历史限定验收保持。正式 bridge/Service、双 ABI、受控数据通路、DHCP/DNS、恢复事务及资源回归见 [P02 报告](../verification/p02/report.md)。冻结报告的待审措辞不补写。
- **结构精简**：已通过 [PR #7](https://github.com/zzwtsy/Chuanmen/pull/7) 合并，当前基线工程 CI 通过；专项设备矩阵及 release 冒烟已取消，当前 APK 的设备效果未验证，不标成全量验收通过。
- **既有附加失败**：API24 DNS 与 API37 TCP 在历史 P02 和重构候选同类复现，均不计通过，Android 根因未知。结果继续定位于 PR #7 历史记录，不作为本轮补验任务。
- **P03–P07**：`planned`。已有身份/草稿/观测基础在各阶段列明，磁盘持久化、完整表单、高级能力及系统扩展尚未实现。计划更新不改变这一事实。

`docs/verification/**`、根 handoff.json、SHA256SUMS 和官网目录快照保持原字节。运输清单只说明原冻结范围。需求映射见 [requirements-traceability.md](../design/requirements-traceability.md)，任务细化格式见 [task-brief.md](../development/task-brief.md)。
