# Chuanmen 路线图

版本：2026-10-13。目标是在现有 Android 模板与交互原型基础上，实现可持续维护、基于 EasyTier 的原生 Android 客户端，并保留已经确认的简洁交互。本文统一维护阶段状态；现有环境与命令见 [开发环境](../development/setup.md)。

## 1. 交付目标与阶段顺序

推荐先证明真实网络与系统生命周期，再补齐配置、可观测性和高级能力。图表、漂亮的连接状态或 JSON 保存成功都不能替代真实通信验收。

| 阶段 | 状态 | 估算 | 核心目标 | 退出时必须拿到的结果 | 实施文件 |
|---|---|---:|---|---|---|
| P00 可行性与证据冻结 | verified（限定范围） | 1–2 周 | 选择上游版本，证明 Android 接入可行 | 固定 commit 与补丁决策；真实设备上的 fd / protect / 双向流量证据 | [P00](p00-feasibility.md) |
| P01 工程基础 | in_progress | 1 周 | 可复现构建、模块、主题与 AI 协作入口 | 干净环境构建；基础 CI；实际可运行的命令与 demo 数据边界 | [P01](p01-foundation.md) |
| P02 核心与 VPN | planned | 3–4 周 | 建立可靠的最小真实连接闭环 | 授权、连接、取消、断开、网络变化与资源释放均可观察和验证 | [P02](p02-vpn-core.md) |
| P03 配置闭环 | planned | 2–3 周 | 基础/完整配置共用草稿，保存与应用分离 | 本地名称独立；关键字段往返；失败不伪造运行快照 | [P03](p03-configuration.md) |
| P04 可观测性与页面 | planned | 2–3 周 | 总览、设备、流量、双日志接入真实数据 | 每项指标有来源和口径；未知值、过期数据与空闲数据正确区分 | [P04](p04-observability-ui.md) |
| P05 高级网络能力 | planned | 3–4 周 | 覆盖官网助手在 Android 上适用的配置 | 路由、出口、DNS、ACL、代理、Portal 等逐项实证；导入导出兼容 | [P05](p05-advanced-networking.md) |
| P06 可靠性与体验加固 | planned | 2–3 周 | 验证系统限制、安全、性能和可访问性 | 真机矩阵、故障恢复、长时间运行、脱敏和大字体验收 | [P06](p06-hardening.md) |
| P07 Beta 与发布 | planned | 1–2 周 | 完成发布准备与回滚能力 | 内测问题收敛、升级路径、合规资料与正式发布评审 | [P07](p07-release.md) |

按一位熟悉 Android 和 Rust 的全职工程师、配合 AI 实施与评审估算，八阶段基础工作量合计约 **15–22 周**。建议另预留约 20% 缓冲，向上取整后预算按 **18–27 个自然周**安排；商店审核、外部上游等待和重大平台缺陷可能增加日历时间。不是给每个 AI 代理各分一个阶段就能按代理数量等比例压缩。

## 2. 里程碑与发布口径

| 里程碑 | 阶段结束点 | 可以对外准确描述的状态 |
|---|---|---|
| M0 设计基线 | 设计与原型基线 | 有可交互设计、需求约束、配置快照和实施计划 |
| M1 技术可行 | P00 | 选定版本的 Android 数据通路有实证；可以进入工程化 |
| M2 最小可连接版 | P02 | 在验证范围内可以真实连接和断开；功能尚未齐全 |
| M3 可用 Alpha | P04 | 核心配置与日常四页交互形成闭环；高级能力仍按台账推进 |
| M4 功能候选版 | P05 | 所有适用能力有明确实现状态和测试证据；没有未经说明的缺口 |
| M5 Beta 候选 | P06 | 兼容性、恢复、安全和性能达到约定门槛 |
| M6 正式发布 | P07 | 发布与回滚资料完备，完成发布决策 |

如果 P00 不能证明可靠的 `protect()`、fd 所有权或数据通路，后续正式版本排期应重新估算。可以继续用 demo 数据实现 UI，但不能把演示完成率计入原生网络完成率。

## 3. 优先级与范围管理

**P0 是正确性。** 连接状态可信、单实例、配置不丢失、保存不暗中应用、用户主动断开后不自动重连、真实业务流量计量和日志不泄漏秘密。这些不能为赶进度延期。

**P1 是完整日常体验。** 全部适用配置、快捷操作、导入导出、可靠的诊断资料、设备细节和 Android 系统体验。低频不等于不适用；监听、中继与 Portal 需要验证和实现，不能仅为缩短列表删掉。

**P2 是有证据再投入的扩展。** 多进程隔离、更多 ABI、复杂自定义图表库、大规模 Gradle 模块化、更多 Agent Skills 等。仅在出现具体问题、复用需求或测量结果时投入。

当前范围为免 Root、单个活动 VpnService、本地管理多个配置。管理后台、账号系统、云同步、Root 转发、并行运行多个 VPN 和给 App 添加 AI 助手均不属于本路线图的默认范围。

## 4. 哪些工作可以并行

| 组合 | 可以并行的内容 | 需要串行确认的边界 |
|---|---|---|
| P00 内部 | 上游 API / 构建调查、UI 需求梳理、设备准备 | 版本选定后才能确定正式 JNI 契约与构建版本 |
| P01 与设计准备 | 主题、Preview、demo 数据、文案 | 不得为便于假数据而改变真实状态模型 |
| P02 与 P03 前置 | 序列化样例、表单校验、配置目录映射 | 核心解析与保存/应用路径必须对齐 P00 版本 |
| P03 与 P04 前置 | 纯页面组件、数据口径定义、日志脱敏样例 | 接入真实快照前不能验收为运行数据 |
| P05 内部 | ACL、导入导出、代理协议的独立调查与测试 | fd、路由、DNS、默认出口等共享运行时变化要统一协调 |
| P06 内部 | 可访问性、性能、兼容性资料整理 | 发布二进制与修复版本要对应同一 commit |

代理并行时分配不重叠的文件所有权。跨模块接口先定契约，再独立实现；共享 schema、依赖目录和连接协调器由明确责任人合并。

## 5. 决策门槛

| 决策 | 最迟时点 | 所需证据 |
|---|---|---|
| 稳定 tag 加补丁，还是固定主分支 commit | P00 | 构建、必要接口差距、补丁规模、回归代价 |
| 原生 bridge 接口与版本协商 | P00/P02 | JSON/FFI 边界、取消与关闭行为、错误模型、fd 语义 |
| 核心字段是否热应用 | P03，P05 完成覆盖 | 在选定二进制上的成功与失败结果；必要时重建 VPN |
| Portal / 出口 / 子网分享的平台实现 | P00 可行性，P05 完成 | Android 真实设备与对端互操作证据 |
| Material 3 Expressive API 的实验性依赖 | P01，P07 再核 | 官方版本说明、收益、封装范围、回退办法 |
| 是否需要独立 `:vpn` 进程 | P06 之前 | native 崩溃隔离收益与 Binder/恢复复杂度的测量 |

这里的 `:vpn` 模块是构建模块；是否设置 Android `android:process=":vpn"` 是另一个决定。默认先单进程，由服务持有唯一运行状态。

## 6. 进度如何计算

阶段任务只有同时具备代码或明确调查结论、相关验证和结果定位，才算完成。状态采用 `planned / in_progress / blocked / verified`；工具和目录维护不自动构成阶段启动或验收。

- **P00 / M1**：限定 Xiaomi API 36、arm64、4096 字节页及受控 IPv4 场景已验证。历史独立复核完成第二主机空缓存复建与许可技术复核，没有重复真机实验；生产补丁尚未批准，范围外能力继续按后续阶段验收。具体结果、制品身份和缺口以 [P00 报告](../verification/p00/report.md)、[退出边界](../verification/p00/report.md#未验证项与停止条件) 和 [独立复核](../verification/p00/reviews/independent-review.json) 为准。
- **P01**：已实现 `:app -> :contracts`、配置编辑/改名、确定性 demo、四页导航与生命周期收集、主题预览、四个 Android 入口和 Android CI 配置。候选核心/NDK/Rust/ABI 与冻结来源摘要已固定并自动核对；恢复配置按实际内容消除待应用，API 24–25 保留全部 UI 断言并省略截图；本地 41 项 JVM 测试（含 14 项 UI）、15 项工具回归和主题/场景渲染通过。2026-10-12 的全新 checkout 加任务补丁、复用依赖缓存的源码复建通过，live 缺失引擎时明确失败；本次 API 36 设备 14 项 UI 用例与 20 张有效 PNG 验收通过，API 24–25 尚未实测，不继承 JVM 或历史复建结果。阶段保持 `in_progress`，仅剩 Android CI 完整通过门槛：首次 GitHub Actions 在 SDK 安装步骤因命令缺失失败，改用固定版本 Android CLI 后仍需远端复验。空缓存/第二主机不额外作为 P01 门槛，完整真机矩阵与 TalkBack 实测归 P06；具体命令、结果和限制见 [P01](p01-foundation.md)。
- **P02–P07**：正式 VPN/JNI、配置业务、监控页面、高级能力、可靠性与发布工作保持 `planned`。实验探针不等于产品实现。

根 `handoff.json` 与 `SHA256SUMS` 只描述已冻结的 P00 运输范围。其 `p01_p02_started` 字段记录冻结时的状态，不作为当前仓库进度来源，也不随日常开发更新。

不要用文件数量、生成代码行数、UI 能点击或 AI 自报完成率作为里程碑依据。每次阶段评审记录：选定 commit、运行环境、设备、命令、观察值、失败场景、遗留缺口和下一步。

需求追踪见 [requirements-traceability.md](../design/requirements-traceability.md)，通用任务模板见 [task-brief.md](../development/task-brief.md)。
