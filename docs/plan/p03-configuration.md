# P03 · 配置、独立本地元数据与序列化

> 状态：待实施。预计 2–3 周。重点是配置不会丢、状态不会混、保存与应用不会互相冒充；高级能力的完整实机闭环在 P05。

## 1. 目标

以独立本地名称和单一草稿模型完成“创建、编辑、保存、应用、恢复”闭环。
将官网配置范围转成有类型、有来源、有缺省语义的编辑目录。
让基础 / 完整两个 Tab 成为同一份配置的不同视图。

## 2. 前置门槛

- P01 的领域模型、持久化边界、测试夹具和 Compose 基础已可用。
- P00 已冻结实际部署的官网目录与固定核心的配置映射。
- P02 的应用接口已明确；初期可以 fake 驱动，但真实应用验收依赖 P02。
- 阅读总体设计及本包配置目录；37 + 7 是原型快照编辑单元，不是原生叶子参数数量或永久范围上限。
- 不继承网页脚本的对象结构作为数据库格式，需建立版本化领域模型。

## 3. 分任务

### P03-01 · 分离本地元数据与核心参数

1. 为每份配置生成不可变 profileId，所有路由和关联都使用 ID。
2. LocalProfileMetadata 保存显示名、排序与时间，核心网络名另存。
3. 新建提供“配置名称（可选）”，空值时以网络名称生成初始显示名。
4. 对已有配置提供共享标题区的重命名对话框，两个 Tab 不重复字段。
5. 重命名只更新本地元数据，不改变核心配置哈希或应用修订。
6. 改核心网络名称后不擅自覆盖已命名的本地显示名。
7. 删除和恢复配置按 ID 操作，名称重复时也不会操作错网络。
8. 核心 instance_name 如需内部标识，由适配层管理，不能重新绑定本地显示名。

### P03-02 · 实现版本化存储

1. 由配置切片的仓库管理配置与元数据事务；UI 不直接访问 Room / DataStore。
2. 用适合结构化配置的存储保存修订，用偏好存储保存外观等轻设置。
3. 明确网络密码、私钥等敏感字段的加密与备份边界，密钥由系统能力保护。
4. 记录 schemaVersion、configRevision 和来源版本。
5. 保存采用原子事务，进程终止不能留下半份配置或失配元数据。
6. 迁移使用历史 fixture 验证，失败保留原始数据并给恢复入口。
7. 删除操作处理正在运行的配置，不能先删数据库再让 Service 失去归属。
8. 草稿恢复政策写明；保存草稿时同样执行敏感数据保护。
9. 存储格式变化必须说明历史数据如何读取、迁移和失败恢复，运行旧版本、未知字段、显式空列表、Unicode 和迁移中断 fixture；迁移失败保留原件。

### P03-03 · 建立配置目录与转换层

1. 每个编辑单元定义稳定 key、标题、分组、类型、条件和支持能力。
2. 记录官网源字段、固定核心字段、默认来源和平台托管策略。
3. 负向官网选项在转换层映射，不让 UI 文案和保存布尔值方向相反。
4. 区分未指定、显式空列表、非空列表，尤其是监听与路由。
5. u64 等大整数采用无精度损失的类型和文本解析，禁止经浮点中转。
6. 对 URI、CIDR、IP、端口、ACL 和嵌套对象使用结构化校验。
7. 密码“已设置”是 UI 状态，不把圆点或星号写回配置。
8. 隐藏项仍可在历史配置中保留，运行前由平台策略决定可否传递。

### P03-04 · 落实统一草稿和校验

1. Draft 保存 rawInput、解析值、fieldErrors 与基于哪个 savedRevision 编辑。
2. 切 Tab、折叠分组、搜索和导航返回不重建草稿。
3. 无效输入继续显示原文和就近错误，不能自动替换为上次有效值。
4. 校验分字段语法、跨字段约束和运行能力，错误均能定位具体控件。
5. 在用户适当操作时展示错误，避免进入页面就显示红色必填。
6. 基础页只展示普通入网字段；允许为空的密码按核心语义处理。
7. 普通加入场景的连接节点规则不能误伤完整页的合法监听场景。
8. 保存前做完整校验，应用前再经过固定核心解析与平台能力校验。

### P03-05 · 实现基础 / 完整配置页面

1. Tab 固定为“基础配置 / 完整配置”，共有标题和重命名入口。
2. 基础页展示网络名称、网络密码、连接节点三个输入。
3. 自动地址分配显示摘要；已有静态地址必须如实显示，不假装自动。
4. 完整页按网络身份、连接、路由与服务、安全、性能、Android 策略分组。
5. 用同页展开和搜索定位字段；不重新引入分类页、专家页和多级跳转。
6. Android 设置独立一组；平台托管项不在表单或搜索中占位。
7. 搜索同时支持中文名和配置 key，命中后展开分组并保留返回位置。
8. 高级编辑器尚未完成的任务留到 P05，并在内部能力矩阵标明未实现。
9. 对 P00 判定暂未适配但适用的隐藏项，在 P05 通过后恢复字段，不修改原型历史快照。

### P03-06 · 实现保存与应用状态

1. Draft、SavedRevision 和 AppliedSessionSnapshot 独立比较。
2. 正常已应用且无编辑时，不显示“配置已应用”横条或成功占位。
3. 只在未保存、待应用、应用中、已确认失败或结果未知时显示底部操作区。
4. “仅保存”不得改变正在运行的 IP、设备列表和统计会话。
5. “应用”提交确定的保存修订，由 P02 会话事务执行。
6. 未连接时保存不被误判为“更改待应用”，也不暗示已建立连接。
7. 保存 / 应用成功使用短暂 Snackbar；待处理与失败持续可见。
8. 已确认失败后如实呈现恢复结果，不覆盖本地名称与用户仍在编辑的草稿；不能把旧运行快照直接当作当前事实。
9. 避免顶部和底部出现两套相同状态；键盘打开时操作区仍可达。
10. 按 [总体设计操作区](../design/overall-design.md#65-按需操作区)展示 [应用结果确认契约](../design/technical-architecture.md#43-应用结果的确认)，消费 P02 的确认结果，不在 UI 建立另一套查询、停止或重建事务。

### P03-07 · 放置当前网络的流量范围

1. 在设置显示当前查看的配置名称与流量范围摘要。
2. 点击进入完整配置中的 Android 策略组并定位应用范围。
3. all / allowlist / denylist 采用互斥模型，不同时启用两个列表。
4. 设置修改属于当前 profileId，不能读写另一个运行网络的配置。
5. 安装应用清单按平台可见性规则获取，处理卸载、停用和不可见包。
6. 空 allowlist 的 UI 语义必须显式处理，不能意外变成“全部应用”。
7. 应用列表、DNS 与路由修改的生效方式由 P02 TUN 协调器统一判断。
8. 首页不显示流量范围编辑器，也不通过点击实时图进入此设置。

### P03-08 · 序列化与跨版本保护

1. 使用固定核心可解析的 TOML 语义模型，不直接拼接用户字符串。
2. 对已知字段做语义 round-trip，对未知字段保持可恢复记录。
3. 遇到本客户端不可执行的参数给出差异结果，不能静默删除再保存。
4. 区分“原始文件保留”“当前运行配置”和“导出可移植配置”。
5. 为旧版本、未知键、空列表、大整数和 Unicode 名称建立黄金 fixture。
6. P03 交付 codec 与内部预览能力；用户级导入导出闭环由 P05 完成。
7. 每次改目录或转换逻辑同步更新映射版本、相关 fixture 与差异说明。
8. codec 变化必须说明历史数据处理，运行旧版本、未知字段、显式空列表、Unicode 与迁移中断用例；转换失败保留原始数据。
9. 初期以历史样例和行为断言验证兼容性，不为尚无消费方的类型建立通用扫描系统。

## 4. 文件与接口交付物

| 位置 / 接口 | 最小内容 |
|---|---|
| app/feature/configuration/codec/ | 有类型配置、目录元数据、三态列表与无损数值 |
| app/feature/configuration/rename/ | 独立本地元数据与稳定 ID |
| app/feature/configuration/storage/ | 配置仓库、原子保存、迁移和秘密保护 |
| app/feature/configuration/ | 双 Tab、共享草稿、搜索、字段定位与条件操作区 |
| app/feature/settings/ | 当前网络范围摘要和外观设置 |
| core-bridge/config/ | 固定版本解析、核心字段与宿主策略转换 |
| test fixtures/config/ | 黄金 TOML、历史 schema、错误与未知键样例 |
| docs/verification/p03/ | 字段映射、状态矩阵、迁移与 codec 验证记录 |

## 5. 依赖与并行边界

- 元数据 / 存储、codec 和 Compose 页面可并行，共享领域 key 由一人维护。
- 新 UI 字段不得绕过统一校验或直接修改运行引擎。
- P02 接口稳定前用 fake 验证状态；P02 通过后补真实保存 / 应用路径。
- P05 可并行准备复杂字段编辑器，但不能自行复制另一套草稿状态。
- 修改数据库 schema 或字段语义需同步迁移 fixture，不能只改展示标题。

## 6. 验证与明确通过标准

| 场景 | 通过标准 |
|---|---|
| 本地命名 | 创建可命名；改名不重连、不产生待应用，保存 / 恢复不覆盖名称 |
| 双 Tab | 无效输入、错误、光标相关编辑上下文与保存状态切换后不丢失 |
| 仅保存 | 运行修订、IP 和 sessionId 不变；断开状态不误标待应用 |
| 应用失败 | 已保存内容保留，已确认失败可重试；运行状态如实反映恢复结果 |
| 应用结果未知 | 回执丢失不显示成功或已确认失败；旧快照只作历史，再次应用被阻止、显式停止可用，核对或停止确认后重建才能解除限制 |
| 多配置隔离 | A 运行时编辑 B，A 的草稿、应用范围和数据不被改动 |
| 目录范围 | 快照 37 核心 + 7 Android 及重审恢复项映射完整；最终不适用项不在搜索出现 |
| 无损数值 | u64 边界、空列表、缺省与显式 false 的往返语义准确 |
| 未知字段 | 读取保存不会静默丢弃；运行时不擅自启用不可执行参数 |
| 密码与错误 | 掩码不入库；敏感值不出日志，输入错误可定位 |
| 崩溃恢复 | 中途终止不留下部分提交，历史迁移能验证并保留失败原件 |
| 存储 / codec 兼容 | 变化说明历史数据处理，旧版本、未知字段、显式空列表、Unicode 和迁移中断 fixture 全部通过，失败保留原始数据 |

UI 断言应验证用户可见结果；不写只镜像实现细节的状态快照测试。
P05 前的完整页结构通过，不代表所有高级能力已经支持。

## 7. 失败回退与本阶段不做

- 存储迁移失败时保留旧数据与恢复入口，禁止清库“修复”。
- 核心拒绝配置时显示对应错误，禁止自动删除字段后反复重试。
- 不确定的未知参数保留原件，停止应用并说明差异，避免悄然改变网络行为。
- 不增加远程配置账号、订阅服务或公网配置管理服务器。
- 不增加“应用名称 = 网络名称 = 本设备名称”的联动简化。
- 本阶段不以静态表单可以保存作为高级网络功能验收。
