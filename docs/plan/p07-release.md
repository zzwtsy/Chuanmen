# P07 · GitHub APK 发布准备与维护交接

实施依据：2026-10-23 计划；状态以 [路线图](ROADMAP.md) 为准。本阶段的完成结果是可审阅的发布材料与 APK 构建产物，不是已经对外发布。没有 Play/AAB、Beta 招募、设备安装升级或 release 冒烟任务。

## 1. 开始条件与交付边界

P03–P06 已分别达到工程退出条件；候选源码没有未解决的承诺范围阻塞项。固定核心、工具链、配置 schema、版本和支持 ABI 可从仓库定位。按 P07-01 至 P07-08 执行。P07-01 固定候选前先完成预定的版本、README、许可和维护文档修改；后续任务主要核对这些已提交内容并生成 build 下的材料。发现仍需修改候选树时返回 P07-01 固定新 SHA，并重跑受影响检查，不能拿旧 SHA 绑定新源码。

签名密钥访问、创建 tag、上传 APK 和发布 GitHub Release 不在本阶段授权内。未另行授权时构建 unsigned release，材料中明确标记未签名；不把未签名包描述为可安装发行包。发布授权是实际执行时的条件，不阻止本阶段完成本地材料。

## 2. 产物位置与内容

本阶段新增产物按候选完整 SHA 隔离，根目录为 `app/build/release-preparation/<完整SHA>/`，以下文件均为未来交付物，不表示当前已存在：

| 文件 | 内容和通过条件 |
|---|---|
| candidate.json | sourceSha、sourceDirty、versionName、versionCode、applicationId、minSdk、targetSdk、abis、coreCommit、schemaVersion、toolchain；从实际输入读取且与 APK 静态信息一致 |
| checks.json | 每个工程命令的 command、exitCode、logPath、startedAt、finishedAt；所有必需命令退出 0，路径相对候选根目录 |
| artifacts.json | 每个交付文件的相对 path、sizeBytes、sha256、variant、signingState；摘要以生成后的实际字节计算 |
| release-notes.md | 用户变化、配置兼容、已实现范围、设备未验证、未签名/未发布及实际发布待办 |
| known-issues.md | 缺陷 ID、复现输入、影响、责任任务、阻塞与否；退出时无承诺范围阻塞项 |
| sources-and-licenses.md | 自有源码 SHA、上游源码 commit/取得方式、补丁、依赖许可、复建和重新链接步骤 |
| symbols/ | 对应本次 release 的 R8 mapping 和两个 ABI 的 native 调试信息；每个文件列入 artifacts.json |
| logs/ | 本候选实际命令输出；只保留本地忽略目录，不提交个人路径和凭据 |

`artifacts.json` 不包含自身，避免自引用摘要；checks/notes 等文本生成完毕后也列入清单。写入后重新计算所有清单条目的大小与摘要，任一不一致即失败。长期维护规则放既有开发文档；阶段实施记录只保存身份和相对产物路径，不把整包复制进 Git。

## 3. 分任务

### P07-01 · 固定候选源码与版本

**开始条件**：P03–P06 工程退出已记录；所有承诺范围阻塞项关闭。

**修改位置**：app/build.gradle.kts（仅需调整版本时）、候选 candidate.json/checks.json、本阶段实施记录。

1. 先完成版本调整、README 用户说明、来源/许可证和开发维护说明的预定修改，内容分别遵循 P07-04/07；此时允许在 local-working-tree 目录预备材料。按 Git 工作流形成可定位提交后，再进入候选构建。在发布准备记录中填写完整 Git SHA、工作区是否干净、versionName、versionCode、applicationId、min/target SDK、ABI、核心 commit、工具链版本及配置 schema。值从实际配置读取，不照抄计划中的示例。
2. 读取已发布 GitHub Release 及对应构建配置的 versionCode，按版本治理检查新值大于已分发版本；不能从 tag 的字典序推断安装序号。无法取得历史版本时标记 ReleaseHistoryUnknown，禁止声称版本序号校验通过。没有历史分发时明确记录“首次候选”，不虚构升级来源。版本修改属于独立可审查 diff。
3. 从该源码运行完整工程检查组合，保存日志到忽略的 app/build 下；记录命令、退出码和检查时间。任何失败均回到对应阶段修复，不能凭旧 main 的 CI 通过候选。

**失败处理**：版本历史缺失、工作区未固定或工程命令失败时只保留预备材料，不能进入正式候选归档步骤。

**完成断言**：记录中的 SHA 能定位完整源码；检查对应同一源码和锁文件；工作区存在未提交变更时只能在 app/build/release-preparation/local-working-tree 下生成预备材料，并记录基准 SHA 与差异摘要；本任务尚未完成。完成候选身份需按既有 Git 工作流得到可定位提交，不自动借此取得提交或合并权限。

### P07-02 · 检查配置升级与失败恢复契约

**开始条件**：P07-01 已固定候选身份和版本；存储 schema 来源可定位。

**修改位置**：lib/profile 及导入格式的测试、候选 checks.json/known-issues.md；只有测试暴露缺陷时才回到原任务修改生产代码。

1. 从已经真实存在的存储 schema 建立合成 fixture，验证升级至当前 schema、未来版本拒绝、损坏输入保留、密钥失效和写入中断。没有旧发布 schema 时仅测试当前版本及拒绝路径，不添加虚构历史迁移实现。
2. 检查升级逻辑不改变 profileId、本地名称、已保存核心配置和 Android 策略；运行状态和草稿不从磁盘恢复。
3. 检查 versionCode、包名和签名要求的静态兼容条件，并在用户说明中注明真实覆盖安装、系统备份恢复和跨设备行为未验证。

**失败处理**：任一迁移 fixture 改变身份/名称、未来版本被接受或故障写入破坏原件时，登记阻塞缺陷，返回 P03/P05 修复，并重新固定候选身份。

**完成断言**：宿主迁移/拒绝/原子写入测试通过；记录不使用“安装升级已通过”等设备结论。

### P07-03 · 准备 APK 与供应链材料

**开始条件**：P07-02 通过且候选源码未变化。

**修改位置**：候选目录、native 构建产物收集；缺调试信息时修改实际 native 构建配置后重新执行 P07-01。

1. 构建 debug、unsigned release 和 androidTest APK；对 debug/release 运行 check_apk.py，核对 arm64-v8a、x86_64 库字节、ELF LOAD 与 ZIP 16 KB 对齐。
2. 在 app/build/release-preparation 下生成本候选独立清单，逐项记录文件名、字节数和 SHA-256。清单仅包含本候选产物，不修改历史 SHA256SUMS。
3. 收集当前应用许可证、固定核心及依赖许可证、上游来源、全部适配补丁和复建步骤。针对 LGPL 核心列明源码取得和替换/重新链接路径；不能用一个仓库链接代替实际对应版本与补丁。
4. 保存 app/build/outputs/mapping/release/mapping.txt，并从该次 native 构建收集 arm64-v8a/x86_64 对应未剥离调试信息；按实际 build 输出复制至 symbols/，用 ELF build-id（若提供）或构建关联记录匹配打包库。不存在的符号说明缺失原因并补齐构建产物，不能写“已归档”。材料不得包含凭据、设备标识或个人目录。

**失败处理**：缺文件、摘要不符、许可缺失或无法匹配符号时保持本任务未完成；不得把历史产物复制进来补齐当前候选。

**完成断言**：清单中的文件均存在且摘要重新计算一致；APK 静态检查通过；许可证、源码、补丁、符号与同一候选对应。静态对齐通过不表示 16 KB 设备运行通过。

### P07-04 · 编写安装前说明与功能限制

**开始条件**：P07-03 的 APK、来源、许可证和符号清单已生成。

**修改位置**：核对 P07-01 已提交的 README.md，生成候选 release-notes.md；不创建对外 Release。README 仍需修改时先返回 P07-01 更新候选。

1. 在 README 和候选发布说明中解释配置创建、仅保存、应用、恢复失败、导入导出及包含秘密的完整备份操作。
2. 明确本地配置名、核心网络名、本设备名的区别；说明默认不自动连接，以及 API 29+ Always-on 的系统设置入口和关闭方式。
3. 列出工程已实现范围、设备未验证范围、最低 SDK 和 ABI 声明；不把历史 P02 的设备结论推广至当前候选。
4. 为无设备数据、无流量、DNS 错误、应用分流和 IPv6 不可用提供与实际错误码一致的操作说明；不建议通过公开上传完整配置排障。

**失败处理**：文案与代码不符时先改文案；若代码缺少承诺功能，登记阻塞并回原阶段修复，不通过删掉承诺范围完成发布准备。

**完成断言**：每条用户操作均有当前实现入口；每项限制能对应能力台账或测试边界；无 Play 链接、Beta 招募安排或尚不存在的截图/附件链接。

### P07-05 · 整理缺陷与支持范围

**开始条件**：P07-04 文案中的功能入口已逐条对照代码。

**修改位置**：候选 known-issues.md 与 release-notes.md；问题提交所需字段写入 README 的排障说明，不虚构当前不存在的问题模板文件。

1. 汇总 P03–P06 的未解决问题，逐条记录触发条件、影响、当前处理和所属任务。承诺范围功能未实现或工程检查失败为阻塞项，必须修复后才进入下一任务。
2. 设备效果未验证单列为范围说明，不伪装为测试通过，也不再展开已取消的设备任务清单。
3. 使用一条合成配置问题填写排障说明中的问题记录字段：只收版本、最小步骤、预期/实际结果及用户主动选择的脱敏日志，不要求密码、完整配置或设备稳定标识。

**失败处理**：发现阻塞项后停止进入 P07-06，修复后重做受影响候选检查。设备执行取消不是缺陷修复，也不能记为已验证。

**完成断言**：阻塞项为零；范围说明完整；本任务不招募测试者、不发送反馈请求、不收集设备数据。

### P07-06 · 形成待授权发布执行包

**开始条件**：P07-05 确认无阻塞项；清单摘要一致。

**修改位置**：候选 release-notes.md 的待授权执行步骤和 artifacts.json 的签名状态。

1. 准备本地发布说明、候选产物清单、检查结果、源码和许可证链接、签名状态与回退说明。签名尚未执行时，签名身份和签名后摘要写“待发布授权后生成”。
2. 写明实际发布顺序：核对已审阅 SHA → 获得签名/tag/上传授权 → 用批准的密钥签名 → 验证签名与 APK 静态检查 → 重新计算最终摘要 → 创建对应 tag → 上传并核对下载摘要。签名后 APK 与 unsigned APK 分别记录，不复用摘要。
3. 当前执行到本地材料完成即停止。禁止自动访问密钥、创建 tag、推送或建立公开 Release；未签名产物只作为准备材料。

**失败处理**：尚无签名/tag/上传授权只保留待执行标记，不访问密钥、不上传；候选 SHA 或摘要与已审阅材料不符则先更新材料并复核，不能直接发布。

**完成断言**：审阅者能从材料定位候选源码、已完成检查、待授权动作及最终摘要生成方法；发布尚未执行的状态清楚可见。实际授权之后仍不恢复已取消的设备验收。

### P07-07 · 编写维护与核心升级步骤

**开始条件**：P07-06 的本地执行包完整。

**修改位置**：核对 P07-01 已提交的 docs/development/setup.md、versioning.md、git-workflow.md 相关入口；发现错误需修改时返回 P07-01 更新候选。不修改固定核心或执行升级。

1. 更新开发环境和版本治理：问题修复从当前 main 建短期分支，说明受影响字段、行为与回归入口；PR 和合并遵守现有 Git 工作流。
2. 核心升级必须更新 inputs、锁文件、补丁后像、配置映射和许可证，并执行解析/序列化、JNI 所有权、平台策略及 APK 静态回归；不能只改下载 URL。
3. 发现工程回归时保留失败输入和旧候选，不覆盖已发布文件。新版本使用新的 versionCode 和产物身份。

**失败处理**：命令或路径不存在时修正文档，不以猜测的升级脚本补齐说明；本任务只写维护步骤，不顺带升级依赖。

**完成断言**：维护步骤引用仓库中实际存在的命令和文件；没有退役模块、旧脚本或自动发布动作。

### P07-08 · 完成交接

**开始条件**：P07-01 至 P07-07 的产物和断言均已核对。

**修改位置**：本文件末尾实施记录与 ROADMAP；冻结证据目录不变。

阶段收尾记录作为独立文档变更，记录中的 candidateSourceSha 固定指向已经检查的候选，不因报告提交而改写为报告提交的 SHA。实际发布仍使用 candidateSourceSha；若决定把新报告也纳入发布 tag，则必须重新固定并检查该新候选。

在本文件末尾登记 P07-01 至 P07-07 的产物路径、源码身份、检查结果、范围限制和待授权发布动作。逐条读取 candidate/checks/artifacts 并重新核对文件摘要，缺一项则保持未完成；不存在的本地包不能仅用文档链接代替。全部准备材料完成后，路线图标记 verified（工程范围），里程碑写“发布准备完成”；不能写“正式发布完成”。

交接保留 app/build 中可重建产物与仓库中的长期说明，不把临时构建日志全部入库，不生成新的冻结实验包。未来功能排期另行提出，不在本阶段擅自恢复设备验收或新增商店分发。

**失败处理**：候选文件已丢失、摘要改变或任务结果缺失时退回对应任务重建和复核，不能只修正报告为通过。

**完成断言**：candidate/checks/artifacts 的字段齐全，清单所有文件复核成功，7 项输入材料存在，路线图只记发布准备完成。

## 4. 阶段完成断言

P07-01 至 P07-08 均完成；同一候选的工程检查、APK 静态检查、摘要、许可证和来源材料可定位；所有承诺范围阻塞项关闭；发布说明明确未签名/未发布及设备效果未验证。签名、tag、上传未获授权不妨碍“发布准备完成”，但绝不能计为这些动作已经完成。
