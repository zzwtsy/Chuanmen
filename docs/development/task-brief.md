# AI 实施任务 Brief 模板

> 用途：为需要明确边界与验收的复杂实施任务提供模板，可在任务说明或评审记录中填写。普通维护不强制新增永久 brief 或证据包；不要把八阶段一次性交给 AI 执行。

## 1. 任务身份

| 项目 | 填写内容 |

| 任务 ID | 例如 P03-06-A |

| 所属阶段 / 类型 | 对应阶段文件与小节，或仓库维护；注明普通开发、实验或阶段验收 |

| 当前状态 | 待开始 / 进行中 / 阻塞 / 待验收 / 完成 |
| 预计工作量 | 工程时间，外部等待单独列 |
| 优先级 | 阻塞核心链路 / 本阶段必要 / 可独立延后 |

## 5. 必须保持的不变量

从下面选择相关项，删除无关项：

- 本地显示名与核心网络名、设备名、运行快照独立。
- 查看网络与实际运行网络分离，切页面不会切 VPN。
- draft / saved / applied 分离，保存不等于运行生效。
- Service 是唯一会话所有者，UI 不直接调用 JNI 或关闭 fd。
- 队列接受不等于安装完成；旧 session / generation 不污染新状态。
- 用户显式断开后不能被网络恢复或重试重新连接。
- 未知统计不显示为 0，TUN 与对端链路统计不混算。
- 日志、截图、fixture 和 AI 输入不包含生产秘密。
- 隐藏字段不等于删除原配置；暂未适配不等于平台永久不支持。
- 完成状态以真实证据为准，demo 与原型只验证对应层次。

## 6. 实施步骤

1. 读取实际代码与上下文，核对已知事实是否仍成立。
2. 明确需要改变的最小接口 / 状态转移，写出实现顺序。
3. 选择能复现问题或验证边界的 fixture，必要时先建立行为测试。
4. 实现主路径与具体失败处理，复用现有公共组件 / codec / 状态机。
5. 运行与本风险相称的检查，检查实际输出而不只列命令。
6. 更新受影响文档、fixture、目录或 ADR。
7. 汇总证据、剩余限制和审阅重点。

对实验型任务，将步骤 3–5 替换为“假设—实验—观察—结论”。
不要在数据面尚未验证前扩大到完整 UI 或批量高级字段。

## 7. 验收标准

| ID | 条件 / 操作 | 可观察结果 | 验证层次 | 证据路径 |
|---|---|---|---|---|
| AC-01 | 正常场景 |  | JVM / demo / 真机 |  |
| AC-02 | 失败场景 |  |  |  |
| AC-03 | 取消或状态切换 |  |  |  |
| AC-04 | 本任务特定边界 |  |  |  |

- 通过标准应有明确结果，避免“逻辑正确”“体验良好”“测试通过”等空泛措辞。
- 真机依赖任务必须有设备、系统、网络条件与重复次数。
- 只验证用户行为风险，避免编写镜像实现的测试。
- 不扩大测试到无关领域，除非新证据表明确有风险。
- 缺设备或平台权限时写未执行及复现步骤，不计入通过。

## 11. 可直接交给 AI 的任务指令

> 请完成任务 [ID]。先读取上列必读上下文与实际代码，再核对事实、允许文件和验收条件。只在声明范围内实施，复用现有契约，不擅自扩大功能、升级依赖或改共享规则。必要行为测试说明中文条件、操作和可观察结果。使用真实存在的命令验证，并提交完成报告；没有执行的检查必须标未执行。需要新能力或范围变化时先给具体证据和可审阅方案，不用猜测补齐。

## 12. 填写示例：本地配置重命名

- 任务：P03-01-B，已有配置的本地重命名。
- 条件：A 网络正在运行，用户打开 B 网络配置并修改 B 的本地名称。
- 预期：B 名称立即更新；A 会话、B 核心配置修订与两者应用状态都不改变。
- 边界：空白名称的处理遵循统一命名规则；取消不保存。
- 额外验证：之后保存 B 的核心参数、恢复运行配置仍不覆盖 B 的本地名称。
- 最小检查：领域 / 仓库行为测试 + 共用对话框交互测试。
- 真实引擎依赖：此任务不需要真实 VPN 连通，不应为它机械重跑全部网络矩阵。
