# Android UI 局部 AGENTS.md 样板

**状态：参考样板，不是活动指令。** 当前单 app 工程只使用根指令；仅在出现根文件无法清楚表达的 UI 约束时提炼必要差异。本文件不要求新增局部指令，也不要求每个任务都阅读。

## 适用责任

`app/` 负责 Compose 界面、导航和依赖装配。业务规则与运行会话由既定领域/服务边界处理；局部指令只补充 UI 约束，根不变量不在此复制。

## 应写入的具体导航

落地时填入并验证四类真实入口：主题/设计令牌、导航宿主、`features/<功能>` 的 Screen/UiState/ViewModel、相关镜像 JVM/UI 测试。未创建的文件不要填成看似真实的路径；先在阶段计划保留任务。

## 组件与状态约束

- 根装配订阅五个功能 ViewModel；各功能 ViewModel 投影自己的 UiState 并直接处理业务动作，Screen 只接收状态和回调。共享组件不读取仓库或客户端，不导入功能切片。
- 公共外观复用主题令牌与现有组件；选择器、弹窗和提示遵守总体设计中的交互方式。修改一个视觉组件时检查所有调用位置。
- 生命周期副作用集中且有清理条件；重组不触发再次连接、重复采样或重复提示。
- 用户可见文案放资源文件；错误与状态通过可翻译信息表达，不展示内部 DTO 名称。
- 输入草稿、展开状态和滚动恢复各有明确 owner；切换标签时不重新创建另一份配置状态。

可保存的弹窗、展开和滚动状态就近放在功能组件中；草稿归配置 ViewModel，真实会话归 Service。合成输入只在 test/androidTest 构造，不在正式应用添加 Preview、演示仓库或样例状态。

## UI 验证选择

| 变更 | 最小必要验证 |
|---|---|
| 文案或静态排版 | 对应真实状态下检查长文本/大字体是否截断；不机械新增镜像测试 |
| 表单、按钮或提示逻辑 | 语义定位下的用户动作和结果；必要时领域状态回归 |
| 主题/组件令牌 | 代表性浅色/深色/固定动态色，关键组件截图差异 |
| 导航或状态恢复 | 返回、标签切换、配置草稿、Activity 重建的相关场景 |
| 图表 | 固定数据与时钟下的空、零、缺样本、正常趋势；不添加用户未要求的交互 |

语义描述先满足真实用户与无障碍，再辅助测试；不向可访问描述塞测试 ID。纯测试定位标签只在确有必要时增加，保持稳定。[Compose Semantics](https://developer.android.com/develop/ui/compose/testing/semantics)。
