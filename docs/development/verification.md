# 验证与历史证据

常规开发使用相关测试、构建与 lint；技术不确定性或只能由设备观察的行为才需要专门实验。当前命令见 [开发环境](setup.md)，目录见 [ADR 0005](../design/adr/0005-single-app.md)。

## 当前计划的验证范围

2026-10-23 起，结构精简设备补验和 P03–P07 全部设备验收取消，包括模拟器、真机、release 冒烟、安装升级、长时运行、耗电、TalkBack 与 16 KB runtime。现行阶段仅采用 [工程检查组合](setup.md#工程阶段检查组合)，androidTest 只编译。下文的设备实验规则保留用于理解历史记录；本轮不启动实验，不生成新冻结证据包。

本轮报告使用三种独立字段：实施状态（未开始/进行中/已完成/有具体阻塞）、工程检查结果（passed/failed/not_run）和设备范围（not_planned，结果仍未验证）。取消设备执行只改变范围，不把设备结果改为 passed，也不把所有功能任务改为 blocked。

## 验证范围

静态、JVM、native 宿主、APK 构建、模拟器和真机分别报告。JNI pipe 不能证明 VPN 业务连通，静态 16 KB 对齐不能证明 16 KB runtime，界面显示已连接不能证明 peer 回包。新 APK 不继承旧设备验收。

可长期复用的行为放入 app 标准测试目录或 app/native/tests；真实设备回归与受控 peer 归 scripts/android。保留的历史设备判据包含完整 instrumentation 身份、应用报告、实际 APK 摘要和 peer 的请求/响应关联。缺测为 null，缺报、跳过或只退出 0 均不算通过。

## 实验只解决明确问题

开始前用简短声明写清：问题和工程决策、固定输入、设备/网络范围、操作和可观察判据、次数/时长预算、失败停止条件、资源关闭安排。遇到来源不匹配、授权不足、对端不受控或资源无法确认收束时停止，不无限重试直到成功。

临时输出留忽略目录；只在确有独立实验时按问题新建源码位置，不恢复全套实验框架。结束时将有效场景转正式测试、保留最小探针或退役；不永久维护一次性复核工具。普通代码变更不自动产生阶段 manifest、发布流水线或运输包。

受控 peer 运行 10–1800 秒，使用独立 p02-* 请求身份和新输出目录；不创建宿主 TUN/路由。设备回归结束后请求 peer 停止，核对线程、核心及 DNS socket 均收束。CLI 超时不等于设备 Service 已停止，资源未确认时继续调查，不能直接宣称释放成功。

## 证据筛选与隐私

保留关系为：结论 → 判据 → 观察 → 产物身份 → 必要输入。保留关键负向结果和必要原样本，移除重复日志、缓存位置及与结论无关的环境噪声。测量注明单位、时钟、样本数和计算方法；单次结果不推广为稳定性能。

材料入库前先脱敏、扫描、人工检查。不得包含个人主目录、真实序列号或稳定摘要、宿主身份、凭据和不必要的真实端点。公开 namespace、上游作者名称和合成配置 hostname 保留语义。隐私扫描只报告文件位置和规则，不能替代人工判断。

```bash
python3 scripts/check_privacy.py
python3 scripts/check_privacy.py --tree index
```

当前没有自动发布/冻结工具。新阶段确需发布证据时，先明确范围与必要材料，经审阅新增记录；不覆盖旧记录，也不刷新旧摘要来掩盖变化。

## P00 / P02 历史

[P00 报告](../verification/p00/report.md)、[P02 报告](../verification/p02/report.md)、`docs/verification/**`、根 handoff.json 和 SHA256SUMS 的发布字节保持原样。阶段状态由路线图维护；旧记录中“待 CI”“待退出评审”等文字表示写入时的状态。

P00 实验、P02 固定运行复核、证据发布/导出/清理和聚合 handoff 工具已经退役；历史路径按当时工程解释，不能用这些链接判断当前目录缺失或补建旧工具。需要历史源码时从已签名 P02 Git 基线 `872bea7e3898881e4787b0adb012726933cd8329` 取出至独立工作区（例如 `git archive 872bea7e3898881e4787b0adb012726933cd8329` 导出到新目录），依据原记录核对输入；原记录没有精确源码的部分继续保留限制，不补造可复现声明。

历史维护后的脚本与 APK 各有身份，不能凭源码静态通过新增真机结论。既有材料的完整性用原 SHA 清单或精简前后的字节对比核验，不要求日常构建重跑旧发布框架。
