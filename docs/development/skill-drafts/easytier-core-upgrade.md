# 候选技能：easytier-core-upgrade

## 状态与决定

这是**设计规格**，不是 `SKILL.md`，不会被项目技能扫描器当作已实现技能。尚未创建或安装对应的项目技能；文中的升级流程仍待实证，脚本可用性须以实际验证为准。P02 的原生基线、接口与验证证据到位后，再根据重复使用价值决定是否创建。

## 要解决的具体问题

EasyTier 核心、Android 宿主、JNI 桥、配置目录和 UI 能力提示可能独立变化。只更新版本号容易漏掉方法签名、默认值、统计口径、平台补丁或 ABI 的差异。候选技能应该把一次成功的实际升级流程保存下来，使下一次升级能复用证据和验收。

这是本项目基于边界复杂度的判断，不是对某一未验证版本兼容性的结论。规范入口：[EasyTier 官方仓库](https://github.com/EasyTier/EasyTier)、[JNI tips](https://developer.android.com/ndk/guides/jni-tips)。

## 创建门槛

- 已有固定核心 revision 与实际能运行的 Android/native 构建，至少覆盖计划发布的主 ABI。
- 已有 JNI 方法、回调、配置与能力契约；TUN 所有权能被查阅和测试。
- 已有实际 command registry 或经验证的脚本，不需要代理猜 Gradle task 或 native target。
- 至少完成一次升级或严格的升级演练，并保存旧/新环境、失败点、修正和回归结果。
- 能构造一个包含真实不兼容点的脱敏输入，用于验证技能能发现而非掩盖问题。

任一关键输入缺失时，先完成工程基线或普通 runbook，不提前生成大段“升级最佳实践”。从项目实际工件与修正记录提炼技能更符合其价值来源。[创建最佳实践](https://agentskills.io/skill-creation/best-practices)。

## 触发与排除范围

**应触发**：用户要求升级嵌入核心、评估一个新 tag/commit 对 Android 宿主的影响、重放已验证升级检查。

**不应触发**：仅刷新官网助手 UI 字段、修正文案、排查某一次断线、升级与核心无关的 Compose 依赖。配置范围核对由现有 `easytier-config-audit` 处理。

## 未来输入契约

| 输入 | 最少信息 | 缺失处理 |
|---|---|---|
| 当前核心清单 | commit、版本、来源、ABI、补丁、工具链 | 停在基线缺口报告 |
| 目标 | 明确 tag/commit；无法固定时先解析来源 | 不使用不受控“latest”直接实施 |
| 现有桥接契约 | JNI 签名、DTO、能力、错误映射 | 从实际工程提取并核对 |
| 配置目录 | 冻结来源、默认值、显隐与序列化规则 | 请求相应目录审计，禁止猜映射 |
| 验证入口 | 实际存在的 host、ABI、设备和生命周期检查 | 记录未完成的验证门槛 |

## 待实证的工作流

1. 读取项目当前阶段、核心与工具链清单；识别此次修改允许的范围。
2. 固定新旧来源，比较上游改动、导出接口、配置 schema、默认值、能力、许可与补丁影响。
3. 形成明确的升级差异和验证计划。此时任何“兼容”判断都要有接口/运行证据，不能只依据发行说明。
4. 在已授权的隔离分支中更新来源与最小适配；保留必要补丁说明，不无关重构 UI。
5. 调用实际仓库命令验证构建、配置 round-trip、启动/停止/重连、权限撤销、TUN 交接和主 ABI。
6. 对能力增减更新目录与 UI 门控；未验证的新能力保持待验证，不能把开关可见等同于可用。
7. 输出可审阅变更、验证证据、未覆盖平台与回退方式。发布与签名不属于此技能默认范围。

## 未来输出契约

升级报告包含新旧 revision、环境、接口变化、配置/默认变化、能力变化、补丁、风险、验证命令/结果、实际制品标识和未覆盖项。另附最小变更补丁与可执行回退步骤；回退需考虑已迁移的持久化数据，不能笼统写“退回旧 APK 即可”。

## 脚本选择

优先复用工程已经验证的构建、配置审计和设备脚本。只有实际演练中重复出现且容易出错的接口/manifest 对比才新增脚本；版本比对脚本不可自行合并、发布或上传制品。

脚本应有明确依赖、工作目录、参数、失败码和输出。不要为技能额外创建第二条 native 构建流程。[Agent Skills 脚本指南](https://agentskills.io/skill-creation/using-scripts)。

## 上线前评估

至少用一个无变化案例、一个签名/字段不兼容案例、一个验证设备缺失案例比较有/无技能的结果。检查是否找全差异、是否忠实记录未验证项、是否避免改动授权以外范围。格式合法不能代替这些任务效果检查。[技能效果评估](https://agentskills.io/skill-creation/evaluating-skills)。

若一次升级仅靠现有脚本和简短 runbook 已足够稳定，不必把它升级成 skill。
