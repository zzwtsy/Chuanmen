# 候选技能：easytier-vpn-diagnose

## 状态与决定

这是**设计规格**，不是已安装或可调用的技能。P02 先形成真实诊断事件和故障复现，P04 补足监控数据后再评估创建。当前 HTML 原型的模拟日志不足以证明真实排障流程有效。

## 要解决的具体问题

用户说“连接了但访问不到”时，原因可能位于授权、服务、TUN、底层 socket、peer、路由、DNS 或目标服务。候选技能帮助从证据逐步缩小范围，避免看见一条流量曲线就断定组网正常，或见到某种 NAT 类型就直接归因。

排障分层是本项目的建议。平台依据来自 VpnService 的授权、虚拟接口与隧道路径模型，具体日志事件仍须由本项目实现并实证。[Android VPN](https://developer.android.com/develop/connectivity/vpn)。

## 创建门槛

- 已有明确的会话状态、事件码、时间与 `sessionId`，App/core 来源可区分。
- 已有本地只读诊断导出及脱敏规则；密码、私钥、凭据不会进入输入包。
- 至少三类真实可复现故障，包含输入、观测、排查步骤、修复与修复后结果。
- 有确定的测试设备/拓扑和可用验证命令，说明哪些操作会改变当前网络或会话。
- 已定义统计口径：本机 TUN 字节、peer 数据、探测丢包与未知值分别表示什么。

未满足这些条件时只编写普通诊断记录。不能用模型常识编造本项目的事件码、服务类、ADB 包名或虚拟接口名称。[技能创建最佳实践](https://agentskills.io/skill-creation/best-practices)。

## 触发与排除范围

**应触发**：已获得本客户端脱敏诊断包，用户要求分析真实连接/访问异常；开发者要重现某个已记录的 VpnService/native 生命周期故障。

**不应触发**：普通配置目录对齐、UI 重排、无授权扫描其他主机、自动上传用户网络信息、替用户改变系统 VPN 或其他网络设置。缺少诊断输入时先列最小必要证据，不一次索取整份设备数据。

## 未来输入契约

| 输入 | 用途 | 缺失后的结论限制 |
|---|---|---|
| 问题描述与目标 | 哪个 App、哪个目标、何时开始、期望什么 | 不先假定所有流量均应经过 VPN |
| 会话与环境 | 设备/API/ABI、App/core 版本、底层网络、会话 ID | 不把另一会话的事件拼接成因果链 |
| 脱敏配置摘要 | 选中的配置版本、IP/路由/DNS/应用范围 | 不知分流策略时无法判断流量是否应被接管 |
| 事件片段 | 相对时间、source、阶段与错误 | 无事件只能提出待验证假设 |
| 统计与探测 | 单位、采样时间、重置边界与目标 | 单点“0”不等于断网，未知不等于0 |

## 待实证的诊断顺序

1. **核对问题与会话。** 查看网络、运行网络、配置版本和时间是否一致；只做只读分析。
2. **定位最后完成的阶段。** 授权、服务前台运行、核心启动、TUN 建立、peer 可用依次查证，不仅看 UI 标签。
3. **核对应该接管的流量。** 目标地址、App 包名单、路由和 IPv6/DNS 策略是否命中；先解释已有配置，不立即改成全流量代理。
4. **沿数据路径找断点。** 对照 TUN 计数、peer 链路、探测目标与服务响应。持续零、缺样本、计数器重置分开解释。
5. **给出最小验证。** 每个候选原因配一个能区分它的观测或实验，说明会改变什么；优先本地、只读、可回退实验。
6. **经授权的修复与复测。** 用户已授权排障修正时，在范围内一次改变一个变量，记录前后结果；需要中断正在使用的网络或扩大采集范围时再说明原因。
7. **沉淀故障夹具。** 只保留脱敏且可重复的必要片段，不把用户秘密永久写入技能。

## 输出必须区分四类信息

- **已确认事实**：日志/统计/测试直接显示什么。
- **推断**：哪些证据支持哪种原因，仍有什么替代解释。
- **待验证项**：缺什么数据，哪一个最小实验可以区分。
- **修复结果**：执行了哪项已授权操作，复测是否改善，未覆盖什么。

严重性、NAT 类型、版本差异都是线索，不是单独的根因证明。不能把“启动成功”写成“全网已连通”，也不能把“未发现错误日志”写成“没有错误”。

## 未来脚本与权限

复用本项目已有只读诊断导出、时间线归并和夹具重放入口；脚本接受明确输入路径/会话 ID，输出本地脱敏报告。绝不自带远端上传目的地、真实凭据或默认网络扫描。ADB、设备权限和命令名称必须根据实际工程说明，不能假定安装某个 MCP 后才能使用。

每个操作的输入、输出、前提和失败信息应清楚；复杂命令抽入经过执行验证的脚本。[Agent Skills 脚本指南](https://agentskills.io/skill-creation/using-scripts)。

## 上线前评估

用至少三组真实脱敏故障和一组证据不足样例验证，任务提示不能泄露根因。比较无 skill 基线，记录正确定位、错误归因、额外数据请求、无必要破坏性操作和耗时。环境缺失时应输出受限结论，而不是编造终端输出。[技能效果评估](https://agentskills.io/skill-creation/evaluating-skills)。

若诊断流程尚不稳定，继续积累可复现故障；不以“已经写了设计规格”为理由发布技能。
