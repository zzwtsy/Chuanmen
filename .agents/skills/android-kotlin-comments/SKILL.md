# Android / Kotlin 中文注释

以可核验的中文说明减少维护者误解。记录调用契约、实现原因和测试目标；保留准确且有用的既有说明，删除噪声。

## 必须遵守

1. **所有新增或改写的自然语言注释使用简体中文。** 保留准确的代码标识符、API 名称、KDoc 标签、URL 与必要术语。保留许可证、版权声明、生成标记及机器可读工具指令的原文。
2. **为范围内每个新增、修改或明确要求完善说明的测试写清中文意图：什么条件下，执行什么操作，断言什么可观察结果。** 放在测试声明附近；类级概述和只有“准备/执行/验证”的空标题不能替代逐例说明。
3. **先读证据，再写说明。** 依据实现、直接调用点、测试和项目规格，不杜撰业务动机、历史缺陷、兼容原因、线程保证或性能收益。
4. **按任务权限保持改动范围。** 仅审查时不编辑；仅改注释时保留非注释代码、断言、注解、命名、字符串及依赖。更广泛的开发任务只在已授权范围内变更行为。
5. **不给自明代码堆模板。** 不逐行翻译语法，不用注释数量或覆盖率作为完成标准；必要契约不能因名称直观而省略。

## 执行流程

### 1. 确定范围与事实

- 读取适用的 AGENTS.md、模块规范、目标代码及其相关测试。利用现有 diff 和用户指定文件确定边界，不自动扫描并重写全仓。
- 区分应用内部代码、发布 API 与测试。检查仓库是否有 AndroidX 风格、完整参数表或其他既定文档约束。
- 注释涉及 SDK、协程或编译器语义时，检查相关 Gradle 配置、版本目录和真实使用方式；不要默认使用最新版本。
- 记录需要增加、保留、改写或删除的说明。发现文档与代码冲突时，先判断是文档过时还是实现缺陷；无法确认则报告，不把缺陷改写成契约。

### 2. 选择注释形式

| 信息 | 形式与位置 |
| --- | --- |
| 调用方需要的用途、前提、输入输出、失败和资源契约 | 声明处 KDoc |
| 实现选择、不变量、兼容原因、取消与清理边界 | 紧邻相关代码的行注释或短块注释 |
| 测试条件、操作、实际断言的结果 | 每个测试声明附近的中文行注释或 KDoc |
| 不提供签名或代码之外的信息 | 省略或删除冗余说明 |
| 未获证实的原因、缺陷或契约冲突 | 写进审查发现，不当作确定事实写入源码 |

普通应用优先用 KDoc 正文和 `[symbol]` 表达简短契约；长说明或明确的文档规范需要时使用标签。对有完整参数表要求的 API 保留并补齐对应标签。

### 3. 按需读取参考

| 当前任务 | 必读资料 |
| --- | --- |
| KDoc、公开 API、参数/返回/异常或 Kotlin 实现注释 | [Kotlin 与 KDoc](references/kotlin-kdoc.md) |
| Compose 状态、effect、生命周期、稳定性、Modifier、语义 | [Compose 检查](references/compose.md) |
| 任意测试说明，包括协程、Flow、设备和 Compose 测试 | [测试中文说明](references/tests.md) |
| 需要出处、规范冲突或版本行为复核 | [官方依据与适用范围](references/sources.md) |

只读取本次任务需要的资料；从主文档直接打开，不预加载全部参考。

### 4. 完成最小改动

- 用中文直接说明行为、原因和边界；保留英文符号以便与代码对应。
- 测试从前置数据、fake/mock、操作与断言反推意图。已有准确中文说明不重复添加；复杂测试再补具体的“前置/操作/预期”段落。
- 保留项目测试方法名。中文说明不依赖改成中文标识符、含空格反引号名称或新增显示名。
- 同步调整因代码变化失效的 KDoc、参数名和注释；避免在多个位置复制同一契约。
- 对错误或缺乏断言的测试、失实的保证和待证实原因，记录明确缺口。注释任务不擅自修逻辑，也不通过缩小文档来掩盖原有要求。
- 没有代码可读时，只给适用规则或明确标注假设的示例，不声称已完成项目审查。

## 容易写错的边界

- `suspend` 不等于自动后台执行，`val` 不等于深层不可变。
- `LaunchedEffect(Unit)` 不等于页面或应用永久只执行一次；组合生命周期与 Android Lifecycle 不同。
- `rememberSaveable` 不等于持久化存储；停止 Flow 收集不证明全部上游工作已停止。
- 稳定性注解不会自动修复类型；是否跳过重组需要结合编译器模式，不从 `List` 直接推断“必然重组”。
- `contentDescription`、资源字符串、日志、异常消息和 `testTag` 不是待翻译的源码注释。
- `assertExists()` 不证明用户可见；只断言最终状态不证明中间事件序列；模拟状态恢复不等于真实进程恢复验证。
- 测试没有实际验证时，补一句“验证正确”不能使它满足要求。给出覆盖缺口，不虚构验证结果。

## 验证与交付

结束前逐项核对：

- 新写或改写的解释文字均为简体中文；代码符号、工具指令及受保护的原文准确保留。
- 范围内每个应说明的测试都有具体中文意图，且每个声称的结果有真实断言或明确测试机制支持。
- KDoc 链接、标签、参数名与声明一致；没有空标签、虚构样例和重复摘要。
- 注释中的“仅一次”“始终”“线程安全”“无泄漏”“不会重组”等承诺都有依据。
- 仅注释任务的 diff 未改变非注释代码或工具指令。不要用会误判字符串的正则剥除注释来宣称行为一致。
- 使用项目已有且相关的文档/格式校验；只有可能影响构建或行为、或仓库要求时运行必要测试。没有可用构建环境就明确说明，禁止声称通过。不要为纯注释修改新增测试框架、格式工具或完整 CI。

交付时简要说明修改范围、关键契约或测试意图、验证结果和剩余疑点。仅审查时按“位置 → 问题 → 依据 → 建议”列出发现。保留无法证实的事项；没有需要改动的内容就直接说明。
