# Kotlin 与 Android 的 KDoc

## 决策顺序

1. 读取目标模块的注释约定、API 文档配置及相邻代码。
2. 区分调用方契约与实现原因；将前者放在声明的 KDoc，将后者放在相关实现附近。
3. 按实际读者选择粒度。公开类型及公开、受保护成员默认应有有效文档；真正自明的声明和继承契约已充分的 override 可按项目规范省略。内部代码也可能包含必须说明的复杂契约。
4. 对库发布、AndroidX 风格或明确要求参数表的模块，遵循其完整标签规范。不要仅凭模块应用了 Dokka 就认定必须逐项填标签。

## KDoc 写法

- 使用 `/** … */`。首段用简体中文概括行为；必要时另起段说明约束。
- 在正文用 `[parameter]`、`[Type]` 引用真实符号。链接必须在声明上下文可解析；不要通过新增未使用的 import 修饰文档。
- 普通应用默认将简短的参数和返回语义融入正文；说明较长或仓库要求时使用 `@param`、`@return`。
- AndroidX Jetpack API 指南要求显式 `@param`、`@property` 生成完整参数、属性表。这是特定文档规范，不能泛化成所有应用代码的硬要求。
- 标签名、参数名保持原文，描述使用中文；删除失效标签，禁止空标签和“参数就是参数”式描述。
- 主构造函数中的 `val`/`var` 属性用 `@property` 说明；普通构造参数用 `@param`。除非项目明确要求，不为同一属性机械重复两种标签。
- 遵循项目标签顺序；采用 Android 风格时按 `@constructor`、`@receiver`、`@param`、`@property`、`@return`、`@throws`、`@see` 排列，标签续行相对 `@` 缩进四个空格。
- 按需使用 `@receiver`、`@property`、`@constructor`、`@throws`、`@see`。类型参数写 `@param T`，不要写 `@param <T>`。
- 使用 KDoc 的 Markdown 与符号链接，不照搬 Javadoc 的 `{@link …}`、`@deprecated`。弃用机制是 `@Deprecated` 注解；纯注释任务只报告注解问题，不擅自添加或修改它。
- `@sample` 只能引用存在且适配项目样例构建的函数；不要虚构样例符号。
- 不自动增加作者、日期、版本或修改流水账。维护历史交给版本管理；只保留项目要求或有实际维护价值的信息。

## 契约核对表

只描述适用且有证据的项目：

| 维度 | 必须核对的事实 |
| --- | --- |
| 输入 | 单位、有效范围、空值或空集合含义、边界是包含还是排除 |
| 输出 | 返回当前快照还是持续更新、缺失值语义、排序或去重是否有保证 |
| 状态与资源 | 谁拥有状态、谁能更新、谁关闭资源、是否允许重复调用 |
| 失败 | 同步抛出、挂起调用传播、返回失败值、回调报错或状态流错误 |
| 线程与协程 | 实际 dispatcher、调用线程限制、主线程安全性、取消传播 |
| 时间与生命周期 | 缓存有效期、超时范围、作用域结束条件、恢复边界 |

`suspend` 本身不证明后台执行、线程切换、线程安全或主线程安全。异步回调里的错误不等于调用方法会 `throw`。不要罗列无法穷尽的异常；只记录调用方需要处理的真实失败条件。

契约与实现冲突时，检查规格、调用点、测试和必要的历史，区分文档过时与实现缺陷。无法判断时报告冲突，不把当前实现的缺陷重新描述成正式契约。

## 中文示例

下面的示例具有明确实现，展示“空输入、失败结果和边界”等签名无法完整表达的信息。

```kotlin
/**
 * 将 [raw] 解析为非负的商品数量。
 *
 * 忽略两端空白；不是 Int 范围内的整数或结果为负数时返回 null。
 */
fun parseQuantity(raw: String): Int? =
    raw.trim().toIntOrNull()?.takeIf { it >= 0 }
```

这里没有重复增加“参数为字符串”“返回一个整数”等说明。若真实业务类型、输入规则不同，按实际实现重新写，不照抄示例契约。

有参数表要求时，将复杂约束集中到对应标签，避免正文与标签成段重复：

```kotlin
/**
 * 描述分页请求。
 *
 * @property pageIndex 页索引，必须大于或等于 0。
 * @property pageSize 每页条数，范围为 1 到 100，包含两端。
 * @throws IllegalArgumentException 页索引为负数或每页条数超出范围时抛出。
 */
data class PageRequest(val pageIndex: Int, val pageSize: Int) {
    init {
        require(pageIndex >= 0)
        require(pageSize in 1..100)
    }
}
```

## 实现注释的取舍

保留能防止维护者误改的理由：算法不变量、兼容分支、边界处理、资源成对释放，以及经过确认的性能取舍。说明原因及适用条件，不逐行翻译语法。

- 低价值：`// 遍历列表。`
- 有价值但需要证据：`// 保留服务端顺序，避免同优先级项目在刷新后跳动。`
- 不可信：`// 这样性能最好。`
- 更可验证：说明减少了哪类重复计算；只有存在对应基准或分析结果时才写具体性能数字。

删除过时、错误、与代码重复的注释；准确且有价值的原注释可原样保留。普通被注释掉的死代码在清理范围内可删除，但不要将许可证、工具指令或嵌入式样例误判成死代码。兼容说明和 TODO 若有真实 issue，保留链接并说明移除条件；没有证据时不编造编号、负责人、事故或期限。
