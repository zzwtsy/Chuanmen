# 审计输入与结果契约

依赖 Python 3.10+ 标准库。脚本位于项目根的 `scripts/catalog/audit_config_catalog.py`；此技能是项目级技能，单独复制到其他仓库不会自动获得配置目录或脚本。

| 检查 | 脚本可判断 | 仍需证据 |
|---|---|---|
| 目录键、分组、计数 | 重复/缺失/声明不符 | 合理的新字段是否应该纳入产品 |
| 来源覆盖 | 可见+隐藏映射是否覆盖冻结 sourceFields | 官网现在是否增加了输入 |
| Android 显隐 | 隐藏项是否误入表单/搜索声明 | 所选版本的平台不适用理由是否成立 |
| 基础配置 | 是否保留三个已确认编辑项 | 具体连接模式下字段必填规则 |
| 能力台账 | 键覆盖、验证状态与证据非空 | 证据是否来自真实二进制和设备 |
| 默认值变化 | 比较属性改变，不输出秘密值 | missing、empty、反向 flag 与协议语义是否正确 |

`--report path.json` 将同一 JSON 结果写入指定文件，不改变输入目录。报告路径不能覆盖本次目录输入。调用时对带空格的路径使用 shell 正确引用。

默认快照自动核查项目能力台账与目录哈希。外部 `--catalog` 候选默认只检查目录，报告 `capability_plan_checked=false`；需要时通过 `--capability-plan candidate-capabilities.json` 指定对应台账。不要把没有执行的台账核查写成通过。

差异报告列出字段任意属性（含 children、recommendedDefault）的变化属性名，嵌套内容变化归到其顶层属性，不回显值。重复键同时出现在错误和出现次数差异中；完整读取两者。字段以外的顶层扩展不是本目录契约的一部分，仍需人工语义核对。

退出码：`0` PASS；`1` FAIL 或 REVIEW_REQUIRED；`2` INPUT_ERROR。先核对退出码，再解释错误；不要只检索标准输出里是否有“PASS”。

快照中的 `default`、`uiDefault` 和 `recommendedDefault` 是不同字段。不要直接让推荐值覆盖导入数据，也不要让缺省值被无条件序列化成显式配置。

比较报告将“目录内部一致”与“相对基线发生变化”分开；合法的新字段也应进入评审，所以没有结构错误的版本差异仍退出 `1`。更新快照需要新来源与对应实现台账，不能只改可见总数让测试通过。
